# 无线画布 LibTV 功能域第 8 阶段：工作流与模板中心设计规格

日期：2026-08-13

状态：已确认，进入实施

范围：在既有配方启动器、画布任务图、串/并行执行、取消、重试和中断恢复之上，完善平台级模板预览与运行索引。

## 1. 问题与基线

画布中的 `WorkflowRunner` 已按依赖拓扑排序执行图片、分镜和视频节点，并将运行完整持久化到 Dexie。但 `/workflows` 只展示三张文字配方卡：

- 不直观呈现模板的角色 → 场景 → 分镜任务图；
- 无法查看所有项目的最近运行；
- 无法按运行状态过滤或回到来源项目；
- 无运行记录和读取失败状态。

## 2. 选定方案

扩展 `/workflows` 为“工作流与模板中心”：

1. 每个配方卡显示有序任务图和三步 prompt 摘要，保留带配方参数的项目启动链接。
2. `WorkflowRepository.listAll()` 返回所有项目的运行，按 `updatedAt`、`createdAt`、`id` 稳定降序。
3. 页面并行读取项目与运行，用项目标题解析来源，并展示状态、模式、总进度、节点数和更新时间。
4. 支持全部/运行中/失败/已成功状态过滤，不修改原运行快照。
5. 每条运行链接回来源画布；真正的恢复、重试仍由画布面板执行。

## 3. 数据与安全边界

- 项目和运行仍是唯一事实来源，中心页只读；
- 项目已删除时使用“未知项目”，但不泄露本地异常；
- 不在平台页自动恢复或重试任务，避免隐式产生任何模型调用或远程花费；
- 模板创建仍先返回项目启动器填写意图。

## 4. 可访问性

- 模板图使用有名 `ol`，步骤不依赖箭头颜色；
- 运行过滤使用 `fieldset` / `legend` / radio；
- 运行记录使用有名 section 和 article；
- 进度使用原生 `progress`；
- 加载使用 `role=status`，失败使用 `role=alert`。

## 5. 验收标准

1. 三个配方均可见任务图和原有启动链接。
2. 运行中心聚合全部项目运行，并使用项目标题。
3. 记录序列稳定且显示状态、模式、进度、节点数和时间。
4. 状态过滤不修改持久化数据。
5. 每条记录可回到来源画布处理恢复/重试。
6. 无记录、无匹配与读取失败状态清晰。
7. 第 8 阶段完成后路线图推进至第 9 阶段。
8. 聚焦 Vitest、全量 Vitest、typecheck、build、lint 和 diff-check 通过后独立提交。

## 6. 非目标

- 新建远程 LibTV 模板或同步云端运行；
- 在平台页上编辑任务图；
- 绕过画布选择、会员门禁或真实生成确认；
- 公开部署、远程发布或合并主分支。
