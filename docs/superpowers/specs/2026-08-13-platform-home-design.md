# 无线画布步骤 8：平台型首页设计规格

日期：2026-08-13  
状态：依据用户“不要询问用户，直接完成”执行  
范围：在现有平台壳、项目创建器、本地 Agent/Skill、模型页和社区作品之上，将 `/` 改造为纯本地数据驱动的平台型首页。

## 1. 现有基线与盘点

当前 `/` 由 `ProjectLauncherPage` 承载，已经具备：

- 创作意图输入、三种项目配方、创建/取消/重试和空白画布降级；
- 最近项目读取、项目持久化、hydrate 后进入 `/project/:projectId`；
- `PlatformShell` 下稳定存在 `/models`、`/workflows`、`/agents`、`/discover` 与 `/discover/:workId`；
- Dexie v7 已保存项目、素材、工作流、时间线、社区、协作和会员数据；
- 社区演示种子目前只有 3 条，且只在作品表完全为空时写入，无法给已有数据库补齐后续种子。

本阶段保留上述创建与恢复语义，不重写画布，也不改变既有路由。

## 2. 目标与非目标

### 2.1 目标

1. 在首页首屏提供运营活动横幅、平台定位 Hero、主创建入口和 6 个模式快捷入口。
2. 模式入口创建本地项目，持久化模式提示后进入画布；主按钮滚动/聚焦到保留的创建流程。
3. 提供“说出你的创意”Agent 输入、附件选择和发送；发送后把创意写入项目并进入画布。
4. 按专业影视、商业广告、音乐 MV 展示各 2 张 Skill 卡，含本地封面、作者、使用数和使用入口。
5. 提供 4 条本地模型/工具能力横幅，链接现有 `/models`、`/workflows` 或 `/agents` 页面。
6. 在首页提供 TV Show 社区分类、搜索和至少 8 条本地作品卡；卡片进入既有作品详情。
7. 所有运营、模式、Skill、模型工具和演示作品数据由 Dexie 固定 ID 种子提供，重复初始化不覆盖用户状态、不产生重复数据。

### 2.2 非目标

- 不调用 LibTV、任何外部 API、模型、积分或计费链路。
- 不实现真实文件上传；附件仅保留当前会话中的本地文件名提示，不读取或发送文件内容。
- 不改变 `/discover` 的完整筛选能力和作品管理流程；首页只提供轻量社区入口。
- 不运行 Chromium E2E；最终验证为 Vitest、TypeScript typecheck 和 Vite build。

## 3. 本地首页内容模型

Dexie v8 新增 `homeContent` 表：

```ts
type HomeContentKind = 'activity' | 'mode' | 'skill' | 'capability'

interface HomeContentRecord {
  id: string
  kind: HomeContentKind
  title: string
  description: string
  category?: string
  imageUrl?: string
  author?: string
  usageCount?: number
  targetPath?: string
  prompt?: string
  order: number
}
```

- 固定种子 ID 作为幂等键；初始化只补写缺失 ID，已有记录不覆盖。
- `HomeContentRepository.ensureSeed()` 与 `list()` 是首页唯一内容入口；组件不内嵌业务卡片数组。
- 活动截止时间由本地种子的可重复“活动周期参数”与当前时间计算，倒计时只在页面内更新，不写回数据库。

## 4. 页面结构与交互

### 4.1 运营横幅与 Hero

- 可关闭活动条展示本地文案、倒计时与“立即创作”按钮；关闭状态只在当前挂载周期生效。
- Hero 标题固定为“只需一张画布，连接你的多种创意想法”。
- “新建画布创作”主按钮定位到保留的创建项目表单。
- 6 个模式按钮来自 Dexie；点击后以模式名创建项目，将模式提示写入 `Project.intent`，保存、hydrate 并进入画布。

### 4.2 Agent 与 Skill

- Agent 文本框为空时发送显示可访问校验提示；非空时创建“创意草稿”项目并写入完整创意。
- 附件按钮触发隐藏的多选文件输入，页面只展示文件数量/名称，不读取文件内容。
- Skill 按三类分组，每类 2 张；“使用 Skill”创建本地项目，并将 Skill 提示与名称写入创作意图。
- 创建中的并发、失败、取消和恢复继续复用当前 launcher 操作门禁。

### 4.3 能力条

- 4 条种子分别表达本地视频草稿、导演编排、三维工作流和本地 Agent 能力。
- 使用内部 `Link` 跳到已存在的 `/models`、`/workflows`、`/agents`，不新增外部链接。

### 4.4 TV Show 社区入口

- 分类固定为：全部、精选画布、专业影视、短剧漫剧、商业广告、动漫游戏、教育生活。
- 搜索匹配标题、作者和标签；分类通过作品标签映射筛选。
- 首页加载时执行社区种子补缺，演示集合扩充到 8 条；已有用户作品和已有演示互动数据保持不变。
- 作品卡展示封面、作者、认证徽标、标题、点赞数和“查看创作过程”；封面与按钮均进入 `/discover/:workId`。

## 5. 兼容、状态与可访问性

- 创建表单保留原中文标签、配方、提交按钮、错误恢复和最近项目，既有测试语义继续有效。
- 首页内容或社区加载失败分别显示局部错误，不阻断创建表单。
- 交互按钮具有稳定中文可访问名称；倒计时用 `role=timer`，加载/保存使用 `role=status`，校验/失败使用 `role=alert`。
- 宽屏使用分区网格与瀑布流列布局，窄屏回落到单列；避免固定宽度与横向溢出。

## 6. 验收边界

自动化必须证明：

1. Dexie v7 可升级到 v8，首页种子可补缺且幂等，数据分类/数量正确。
2. 社区种子从 3 条补足到至少 8 条时保留旧记录和互动值。
3. Hero 文案、活动关闭、倒计时、6 个模式入口及模式预置创建正确。
4. Agent 创意发送、空值校验、附件提示与 Skill 分类/使用正确。
5. 能力条链接、社区分类/搜索、认证徽标、点赞数和详情链接正确。
6. 原创建配方、最近项目、平台路由与 `/discover` 详情回归通过。
7. 全量 Vitest、typecheck、build 和 `git diff --check` 通过；不运行 Chromium，不 commit。
