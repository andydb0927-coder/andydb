## 5. 重点结论与后续对齐建议

1. **首要不是继续堆功能，而是收敛节点构图。** Liblib 的关键视觉语言是“媒体卡 + 上浮标题 + 选中后独立 composer”；本地把大量参数内嵌进节点，导致节点高度、遮挡和视口可达性问题持续增加。
2. **图片顶部操作应按模型/状态动态变化。** 该项目的 `Lib Image` 只展示参考/标记/风格；本地固定展示图生图与图片高清，属于明显的状态建模差异。
3. **视频默认值必须模型驱动。** Liblib 当前是 5s、720P、声音开、135 积分、三项高级开关；本地是 3s、标准、声音关、24 积分、单 AutoLink，不能只靠统一静态组件对齐。
4. **保留本地优于 Liblib 的可访问性。** 本地端口、连线业务名称、禁用原因与生成按钮可访问名称更完整，不建议为了视觉复刻而回退。
5. **右键菜单要先决定产品原则。** Liblib 把撤销、粘贴、保存资产等放在一级；本地遵循两级“添加节点/添加资源”并把删除放在节点菜单。两者不能仅靠换文案同时满足，需要明确哪一套作为正式契约。
6. **资源面板不是同一信息架构。** Liblib 工具坞“素材库”是风格/特效入口，而本地是完整项目资产管理。若对齐，可保留本地能力但应改名为“资产管理”，把风格库/特效库恢复为 Liblib 语义的“素材库”。
7. **结果态功能需另选有产出的项目复核。** 本项目不能证明图片 11 项操作条和视频媒体处理层的当前排版；实现前仍应使用有图片/视频结果的 Liblib 项目补一次同版本核验。

### 5.1 对齐执行状态（2026-08-20）

- 第 2 条已闭环：图片节点顶部操作按结果状态切换；有结果态为 `图生图 / 图片高清 / 参考 / 标记 / 风格` 5 项，无结果态仅为 `参考 / 标记 / 风格` 3 项。
