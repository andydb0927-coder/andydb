# 出海转绘批次 1：制作资料与审核领域层

文件日期按本批指令保留为 2026-09-05；实施始于 2026-09-09。本批是领域契约与纯函数，不是界面上线、自动质检、付费生成或客户交付验收。

## 1. 范围和依据

- 用户本批指令为实现范围；客户《审核交付验收标准.pdf》（26 页）为规则来源。下文页码为文件页序，不是章节编号。
- 三个独立命名空间：`dubbing.shot`、`dubbing.localization`、`dubbing.qa`，各自 `schemaVersion: 1`。
- 实现放在 `app/src/features/dubbing/`，不依赖画布/项目/资产主类型，不修改 `NodeKind`、`Asset`、`Project`、数据库版本、现有任务状态机或 provider。
- 资料通过现有资产 ID/剧集 ID 建立语义关联，但本批不读写 IndexedDB、不校验仓储中资产是否存在、不写入旧项目字段。不将 JSON 可序列化描述为已接入刷新恢复。
- 全部测试使用本地固定数据；领域函数不发网络请求。既有 E2E 继续 fixture 拦截，无付费生成。

## 2. 镜头记录 `dubbing-shot-record`

### 2.1 数据字段

| 字段 | 含义与约束 |
| --- | --- |
| id / dramaId / episodeId | 非空稳定标识，记录剧集归属；不复用 NodeKind |
| episodeNumber / shotNumber | 正整数集号、镜号；本版本三位集号范围 1–999 |
| sourceAssetId | 原片资产 ID，保留原片引用而非覆盖 |
| sourceTimecode | `startMs`、`endMs` 安全整数毫秒，`0 ≤ startMs < endMs`，半开区间 `[startMs, endMs)`；不假装精确帧时基或新版片段时长 |
| content | 原台词、本地化台词、景别 framing、机位 camera、去重的 referenceAssetIds；静默镜头允许空台词 |
| generationVersions | 追加的生成版本：稳定版本 ID、请求 ID、provider ID、输出资产 ID 列表、时间、对应返修 ID、当时的内容快照 |
| status | 独立审核业务状态，见下表；与 TaskStatus 的运行成功/失败无关 |
| revisions / revisionCount | 追加返修意见记录及次数；包含轮次、意见 ID、原因、基准版本、标准 ID、人员与时间 |
| approval / delivery | 当前批准所绑定版本、自审记录 ID；交付引用及版本；不代表已操作外部交付系统 |
| events / createdAt / updatedAt | 追加事件记录；时间由调用方注入 ISO UTC 字符串，不能倒序；事件 ID 不得重复 |

领域入口为 `createDubbingShotRecord` 与 `transitionDubbingShot`。返回新对象并复制嵌套输入，保留旧对象、旧版本和旧意见。不提供覆盖版本、删除返修记录或直接改审核状态的业务函数。

### 2.2 状态流转

| 当前状态 | 事件 | 后续状态 | 门槛 |
| --- | --- | --- | --- |
| 待生成 | 编辑草稿 | 待生成 | 字段合法，不消耗返修次数 |
| 待生成 | 提交生成版本 | 待自审 | 有输出资产、全新版本 ID；生成成功不等于通过 |
| 待自审 | 退回返修 | 待返修 | 有反馈，次数尚未达到 3；记录当前版本 |
| 待返修 | 编辑草稿 | 待返修 | 不覆盖上一版的台词/引用快照，不新增返修轮次 |
| 待返修 | 提交修复版本 | 待自审 | 新版本关联本轮返修意见，必须重新自审 |
| 待自审 | 批准 | 已通过 | 明确审核人、自审记录 ID，批准的必须是最新版本 |
| 已通过 | 退回返修 | 待返修 | 未超过 3 次，清除当前批准；历史批准事件保留 |
| 已通过 | 记录交付 | 已交付 | 当前有效批准与最新版本一致，有交付引用 |
| 已交付 | 任意上述写事件 | 拒绝 | 交付记录为本版终态，后续重开策略不在本批 |

PDF 第 12、25 页写的是“各交付节点最多修改 3 次”；本批按用户明确指令收敛为**每个镜头最多 3 次正式退回返修**。草稿编辑、网络重试、生成请求计费不计作客户返修轮次。第三轮仍可提交新版本并通过/交付，第四次退回被拒绝，不清空前面记录。若后续需把内部编辑也计次，必须显式升级业务政策，不静默修改计数。

“待返修→已通过”不是绕过自审的直通路径：修复后先回待自审。`actorId` 和 `selfReviewId` 是审计引用，不是已验证的账号权限或已完成的媒体质检；授权与审核证据仓储在后续接入。

## 3. 本地化方案 `dubbing-localization-plan`

| 字段 | 约束 |
| --- | --- |
| id / dramaId / targetLanguage | 全剧、单目标语种方案；语种由用户选择，不默认为英语 |
| names | characterId、原名、目标名、姓氏；对整剧表校验，不按单集拆开校验 |
| numberRules | 阈值/全单词/待配置，数字例外，句首规则，单位空格；不负责翻译数字拼写 |
| replacements | ID、12 类枚举之一、源元素、目标元素；保留替换而不是模糊/删除作为修复 |
| textReplacements | 独立标记“中文字幕”或“花字”，原文与目标文成对保存 |
| specialRules | 带 PDF 来源页的 EP001、Uber 标志、黑板换白板、煮茶器具换咖啡机项目规则 |

姓名唯一性以 NFKC、合并空白、去首尾空白、忽略大小写的规范键比较：角色 ID、原名、目标完整姓名分别唯一。不同姓氏允许同名；不同剧可复用姓名。复姓/复合名字保留，不按空格强拆；拼音识别、当地姓名真实性和昵称语义仍需人工审校。

十二类固定顺序：建筑、服装、图案、工具、交通、面孔、文字、家具、食物、品牌、日常、祭祀（PDF 第 18、25–26 页）。特殊规则来自客户项目，不自动套用于所有出海项目。

### 数字规则与歧义

- 英语/葡语：小于 10 单词，大于 10 数字；PDF 第 9 页“10 及以下”和第 17、23 页“10 以下”不一致。默认 `thresholdInclusive: null`，输入恰为 10 时返回 `needs-confirmation`。确认后显式设置 true/false。
- 英/葡时间、集数、年龄、金额例外可用数字；句首单词优先。本地化数字判定与文件集号命名分开。
- 西语普通数字使用单词，官方编号与电话号码为数字例外（PDF 第 9、17 页）。
- 未列明的语种默认待配置；允许提供明确项目规则，不能借用英语规则伪造本地化。
- `formatDubbingEpisodeNumber(1)` 为 `EP001`，范围 1–999；不接受 0、负数、小数或截断四位集号。

## 4. 验收模板 `dubbing-qa-standard`

`loadDubbingQaTemplate()` 返回独立可编辑的模板副本；`validateDubbingQaTemplate` 校验 ID 唯一、必填字段、枚举、九大类完整性与 PDF 来源页。模板只有要求，**没有默认通过结果**。

| 等级 | 颜色 | 标签 | PDF 第 1 页含义 |
| --- | --- | --- | --- |
| P0 | 红 | 严重问题 | 必须整改 |
| P1 | 黄 | 一般问题 | 超量必须整改；数量阈值未给出，因此保留 null |
| P2 | 白 | 轻微问题 | 可选择性整改 |

九大类：资产、场景、道具、画面、声音、字幕、修改、交付、中国元素。每条包含 standardId、category、requirement、level、checkMethod（自动/AI辅助/人工）、source（客户PDF、文件名、页码）。等级属于客户成片验收，不混用软件 BUG 台账。

覆盖关键要求：角色/名称/服装一致性，空间/道具顺承，穿帮/闪烁，口型/音轨/版权，字幕与花字、数字规则，3 次返修与全片复查，H.264 MP4 1080×1920/≥25Mbps/25或30fps/双声道、两版海报与 EP001、原片与反馈及修改版分开，十二类元素清单。

`checkMethod` 是计划采用的检查方式，**不代表已执行任何检测**。AI辅助结论不能自动替代人工确认。口型测量、媒体文件检测、字幕安全框、AI识别、甲方飞书上传均未在本批实现。

客户 PDF 部分面孔/族裔排除措辞不作为平台通用自动判废标准：面孔项保留为对照已确认的虚构角色设定进行人工一致性审核，不推断真实人物族裔；来源与适配说明明确保留。

## 5. 兼容、验收和回滚

- 本批只新增领域目录和本规格文档，不修改已有画布枚举、项目/资产模型、序列化/恢复路径、数据库表或生成接口。无迁移，无用户数据清理。
- 新记录采用 JSON 兼容的普通对象、数组、字符串、数字、null；无 Date 实例、Map、Set 或运行时对象混入结果。
- 单测先红后绿：状态流转与拒绝路径、三次上限、重复事件/版本保护、冻结版本快照、时间码合法性、姓名唯一性、12 类替换、特殊规则、数字边界、9 类 QA 模板、损坏模板拒绝、JSON 往返。
- 全量门禁按 typecheck → test:run → build:mock → PLAYWRIGHT_OFFLINE_DIST=dist Playwright 顺序。浏览器回归期间不改源码或重建 dist。
- 本批无新 UI 旅程，不为了增加 E2E 数量制造展示页面；既有全站 E2E 验证兼容性。后续接 UI/仓储时再补刷新、跨项目隔离与用户操作 E2E。
- 回滚本批提交即可移除未接线的领域模块；不需要回滚或删除用户数据。视口收尾与领域层分为两笔提交，分别可回滚。
