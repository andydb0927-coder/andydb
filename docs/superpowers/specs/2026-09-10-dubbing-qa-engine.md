# 出海转绘批 3：QA 自审引擎与交付检查器

## 范围与数据来源

基于批 1 的 `dubbing.qa` 客户 PDF 摘要模板、语种数字规则和批 2 的独立本地工作台。不修改画布、生成 Provider、后端及原 Project/Asset/NodeKind。当前 HEAD 起点 `46d57e2`。

本批是可测的文本/元数据检查，不是视频视觉识别、自动口型检测、AI 质检或实际交付文件解析。工作台“填写检测数据”接受人工测量的 JSON；未提供的数据标 WARN。未知/额外字段、非有限数值、残缺字幕/文件对象拒绝保存。字段说明在弹窗内，示例不自动填入。

## 引擎契约

`runDubbingQa(template, input)` 返回标准 ID、子检查 ID、PASS/FAIL/WARN、依据、检查方式和待确认标记。无时钟、网络和存储副作用。

- 自动子检查 PASS 只表示该输入域和该子条件符合，不代表整个标准通过。
- 人工和 AI 辅助标准始终保留 WARN/待人工确认；自动标准的未覆盖范围也保留待确认（例如集名正确不能证明海报交付完整）。
- 界面所有勾选是独立的人工声明，不改写机器结果。确认表明确记录原始 WARN 与人工确认事实。
- 自动 FAIL 阻断确认表生成；无法靠全勾选覆盖 FAIL。修改数据需清空勾选后重新自审。

## 规则与边界

| 子检查 | 口径 |
| --- | --- |
| 集名 | 严格 `EP001`–`EP999`，大小写、三位数字、无空格后缀；`EP000`/`EP01` 拒绝。只检查提供清单，不冒充读取磁盘。 |
| 连续性 | 从 1 起、不重复、不跳号；提供预期总集数才能确认末尾无缺集，否则 WARN。 |
| 字幕区间 | 毫秒半开区间 `[start,end)`；相邻不重叠，嵌套/乱序/区间相交检测；跨集分开比较；负数/零长度/NaN拒绝。 |
| 字幕排版 | 1–3 行非空文字；归一化安全框默认左右上下各留5%，边界包含。此为明确的项目默认常量，非声称从客户PDF获得精确百分比；客户确认不同值后可修改。 |
| 口型时间差 | 数据驱动常量：绝对偏差 ≤0.3s PASS，>0.3–0.5s WARN，>0.5s FAIL；支持正负偏差，未测量 WARN。 |
| 中文残留 | Unicode Han 正则，覆盖扩展汉字；只检查本地化台词、所给字幕及方案目标花字，不对中文原文误报；不扫描图片文字。 |
| 数字规则 | 复用本地化方案 `dubbingNumberNotation`；西语普通上下文禁阿拉伯数字（NFKC兼容全角）；电话/官方号码须显式声明例外。阈值包含边界未确认时 WARN；不自动猜上下文。 |
| 音量/声道 | 有确认的参考基准才判断±3dB闭区间，不等同LUFS；双声道=2。 |
| 视频元数据 | 1080×1920、H.264/AVC、MP4、≥25Mbps、25/30fps、Rec.709。声道单列检查；不虚构读取文件成功。 |
| 返修 | 已有正式返修计数0–3，批1状态机继续负责不可变历史与上限。 |

## UI 与提交门禁

九节：资产、场景、道具、画面、声音、字幕、修改底线、交付、中国元素；“修改底线”的存储分类仍是旧值“修改”，保证兼容。每节保留模板子项，并有“逐集排查：已核对本集各镜头”标记。标记属于当前镜头/版本，不自动替其他镜头和剧集确认。

批2的“提交生成”依旧仅提交已有生成资产进入待自审，不调用API；“标记自审通过”是本批审核门禁：

1. 全部32个子项（不再只是P0）人工勾选。
2. 九节逐集排查均确认。
3. 无自动 FAIL。
4. 显式生成当前《自审确认表》，才可通过自审。

确认表包含项目、集号、镜号、版本、语种、时间、全部确认项和每条原始检查依据；可本地查看/复制。剪贴板失败可手动从文本框复制。检测数据弹窗Esc关闭、归还焦点；保存错误中文反馈且不丢原记录。

## 持久化、兼容和失效

仍用 `wireless-canvas-dubbing-v1` / `workspaces`。`qa` 新增可选 `evidence`、`checkedCategories`、`confirmation`；历史可选附确认表。旧记录不用迁移，不删除资产，不伪造旧确认表。

确认签名包含当前生成版本、检查输入、完整本地化方案、项目镜头/版本清单和QA模板。新增镜头或版本使现有签名失效；重新生成确认表时重算。修改检测数据、本地化方案会清空待自审勾选；新返修版本重置全部当前QA，旧自审快照保留。写入沿用事务+乐观锁，错误不上报成功。

回滚只撤销本批代码，保留独立数据库与可选字段。本批无真实API、无收费、无生产部署承诺。
