## 2. 官方请求与限制

- 图片统一为 `POST {VITE_SEEDREAM_API_BASE}/images/generations`，Bearer 复用现有 Key。工具固定 Pro `doubao-seedream-5-0-pro-260628`（不继承旧 Lite 兼容 ID），不改变普通图片模型配置。
- 单图参数：`model/prompt/image?/size/response_format/output_format/watermark`。不发送 Pro 不支持的 `sequential_image_generation`。全景/分镜沿用声明式尺寸求解器：1K / 1.5K / 2K，921600–4624220 总像素，宽高比 1/16–16。
- 视频理解使用 `POST {BASE}/chat/completions`，`model` 可复用 `VITE_ARK_TEXT_MODEL_ID` 覆盖，但覆盖款需支持视频理解；`messages` 内为 `video_url` 与 `text`，非流式、关闭 thinking，输出 JSON 分镜片段。
- 视频 URL 需公网可访问，或合法 `data:video/...;base64,...`；官方 URL/内联视频 <50 MB、请求体 <64 MB。支持 MP4/MOV/AVI。本批不新增 Files API/TOS 上传，不支持 blob URL 直接传给云端。大文件需先本地裁短。
- 默认 1 fps（可调 0.2–5）；服务还会按 token 预算抽样压缩，时间戳/分镜边界需人工复核。只读取视频，不自动剪辑/生成媒体。

## 4. 接线与 TDD 计划

1. 为五个图片工具与视频分析冻结 `.invalid` fixture；先写失败测试：参数化提示词、尺寸/数量/串行顺序、结果完整性、鉴权/限流/格式错误、禁用/取消、实际计费与持久化。
2. 工具 Provider 保留原预设 ID，在注册表中替换对应占位，标 `selectorVisible:false`，不混入模型下拉。独立确认窗口复用现有生成队列，不绕开资格校验。
3. 图片预设、Slash、结果工具栏共用同一工具入口。配置缺失时给出原因，音乐/智能粗剪等边界继续禁用。文本分析报告保存版本，可查看、下载并在刷新后恢复。
4. 浏览器 E2E 使用 fixture 验证确认前零请求、串行数量、网格、光影输入图、分析时间段、历史/刷新恢复；离线构建继续 `build:mock`，不得注入真实 Key。
5. 门禁：typecheck → Vitest → build:mock → 全量 Playwright；所有既有测试保持可通过。

## 5. 操作卡

- 本地沿用 `VITE_GENERATION_MODE=seedream-direct-dev`、`VITE_SEEDREAM_API_KEY`、`VITE_SEEDREAM_API_BASE`。不新增账号或 Key；需账号已有 Pro 与豆包模型权限。本批不修改 `.env.local`。
- 图片节点“预设”或结果工具条 → 全景/多格/光影 → 编辑描述与尺寸 → 核对调用次数和费用 → 确认生成。全景结果可用“全景预览”检查接缝；多图结果点击张数展开网格。
- 视频结果“逐帧拉片”创建工具节点，或直接新建逐帧拉片节点 → 选择/上传视频 → 设置抽帧率与维度 → 核对 token 计费提示 → 确认分析 → 查看分镜时间段。
- 线上静态 mock 构建只显示配置未完成；开发 `VITE_` Key 仅供本地验证，生产仍需服务端代理。
- 本轮仅 fixture 验证，不宣称实测画面质量、账号权限或账单。
