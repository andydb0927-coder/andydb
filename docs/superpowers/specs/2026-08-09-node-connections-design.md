# 无线画布节点连线设计规格

日期：2026-08-09
状态：交互设计已批准，待书面规格复核
范围：项目画布中的生成依赖连线

## 1. 目标

让用户在文本、图片、分镜和视频节点之间建立可理解、可编辑、可持久化的生成输入依赖，同时保持当前画布简洁。连线只表达“这个节点的生成参考了哪些上游内容”，不改变时间线顺序。

本轮成功标准是：用户既能拖拽节点端口创建连线，也能通过工具栏依次选择两个节点创建相同的连线；所有合法性检查、撤销历史、自动保存和错误反馈在两种入口中保持一致。

## 2. 已批准的产品决策

1. 同时支持端口拖拽和工具栏点选两种创建方式。
2. 新连线按创作流程限制，而不是允许任意节点互连。
3. 目标节点可以接收多个上游输入。
4. 使用轻量上下文端口：平时隐藏，节点悬停、选中或进入连线模式时显示。
5. 自连、重复连接、循环依赖和类型不兼容均拒绝创建。
6. 创建与删除连接均支持撤销、重做、自动保存和刷新恢复。

## 3. 交互设计

### 3.1 端口与连线外观

- 节点左侧为输入端口，右侧为输出端口。
- 端口在节点悬停、节点选中、键盘聚焦或连线模式激活时显示；其他时间不占据主要视觉层级。
- 默认连接使用低对比度贝塞尔曲线和方向箭头。
- 来源发生变化的连接继续沿用现有警示样式。
- 连接被选中或键盘聚焦后提高亮度，并扩大不可见命中区域，避免细线难以点击。
- 选中连接时，在连接中点附近显示紧凑的“删除连接”操作；该操作不得遮挡节点主操作。

### 3.2 端口拖拽

1. 用户从来源节点右侧输出端口开始拖拽。
2. 拖拽过程中记录当前候选目标。合法目标显示可连接状态；不合法目标仍可被识别，以便在拖拽结束时给出具体错误原因。
3. 放开到合法目标后立即创建一条依赖连接。
4. 放开到空白处时取消，不产生项目修改或撤销历史。
5. 放开到不合法目标时拒绝创建，并显示明确原因。

### 3.3 工具栏点选

1. 用户点击左侧工具栏“连线”。
2. 页面状态提示改为“请选择来源节点”。
3. 用户通过鼠标点击或 `Enter/Space` 选择来源节点。
4. 页面状态提示改为“请选择目标节点”，来源节点保持高亮。
5. 选择合法目标后创建连接，自动切回“选择”工具，并把焦点返回“连线”按钮。
6. 选择不合法目标时保留来源节点和连线模式，显示错误原因，允许重新选择目标。

### 3.4 取消规则

以下操作均取消尚未完成的工具栏连线，不修改项目，也不创建历史记录：

- 按 `Esc`。
- 再次点击“连线”。
- 切换到其他工具。
- 点击画布空白区域。
- 切换项目或离开画布页面。

主动取消后，焦点返回启动连线模式的工具栏按钮；项目切换或页面卸载不执行额外焦点恢复。

## 4. 新连接兼容规则

`preview` 是现有项目中的素材预览节点，本轮在连接规则中按图片素材处理。

| 来源节点 | 允许的目标节点 |
|---|---|
| 文本 `text` | 分镜 `storyboard`、视频 `video` |
| 图片 `image` | 分镜 `storyboard`、视频 `video` |
| 素材预览 `preview` | 分镜 `storyboard`、视频 `video` |
| 分镜 `storyboard` | 视频 `video` |
| 视频 `video` | 无 |

补充规则：

- 同一目标允许多个不同上游输入，例如“角色图片 + 场景图片 + 文本描述 → 分镜”。
- 同一来源与目标之间只允许一条连接。
- 节点不能连接到自身。
- 任何会形成循环依赖的连接都被拒绝。
- 来源或目标不存在时拒绝连接。
- 类型限制只作用于新建连接。载入旧项目时保留既有连接，即使它不符合新规则；系统不会静默删除用户数据。

## 5. 组件边界与数据流

### 5.1 `dependency-policy`

新增纯规则模块，输入项目节点、现有连接、来源节点 ID 和目标节点 ID，输出统一的判定结果：

```ts
type ConnectionValidationResult =
  | { ok: true }
  | {
      ok: false
      reason:
        | 'missing-node'
        | 'self-connection'
        | 'duplicate'
        | 'cycle'
        | 'incompatible-types'
    }
```

该模块不读取 React 状态，不修改 Store，也不生成 ID。端口拖拽、工具栏点选和 Store 防御性校验共用它。

### 5.2 `Project Store`

`project.edges` 继续作为正式连接的唯一数据源，不创建平行的画布连接状态。

- `connectNodes` 在提交前再次执行完整校验，并返回成功或失败结果。
- `disconnectNodes(edgeId)` 原子删除指定连接；不存在的 ID 为无副作用失败。
- 成功创建或删除一条连接各形成一个撤销历史条目。
- 连接变化后，目标节点及其下游结果保留，但标记为“上游来源已变更”，提示用户需要重新生成。
- 撤销、重做恢复完整连接集合和来源变化状态。
- 现有自动保存链负责持久化连接；刷新后从 IndexedDB 恢复。

### 5.3 画布连接控制器

画布层只保存临时交互状态：

```ts
type ConnectionToolState =
  | { phase: 'idle' }
  | { phase: 'selecting-source' }
  | {
      phase: 'selecting-target'
      sourceNodeId: string
    }
```

启动连线模式的按钮使用独立 ref 保存，不进入可序列化的交互状态。控制器负责工具切换、来源高亮、候选目标、取消和焦点恢复。正式连接只在 Store 返回成功后出现。

### 5.4 React Flow 适配

- React Flow 的 `onConnect` 把拖拽结果转换为统一连接命令。
- `isValidConnection` 用于即时可视反馈；拖拽会话同时记录候选目标，并在 `onConnect` 或 `onConnectEnd` 中把结果送入统一连接命令，确保非法目标也能得到具体原因。
- Store 仍执行最终校验，避免 UI 绕过规则。
- 工具栏点选调用同一连接命令，不直接构造或追加 React Flow edge。
- `project.edges` 映射为 React Flow edges，并补充方向箭头、可聚焦标签和选中状态。

## 6. 删除连接

- 鼠标点击连接或键盘聚焦连接后将其设为当前连接。
- 用户可点击“删除连接”，或在连接获得焦点时按 `Delete/Backspace`。
- 删除连接不删除节点、资产、生成版本、任务或时间线片段。
- 删除后目标节点及其下游保留现有结果，但标记为“上游来源已变更”。
- 删除成功后，如果来源节点仍存在，焦点返回来源节点；否则返回可编程聚焦的项目画布区域。
- 删除连接不需要依赖影响确认对话框，因为没有节点或生成结果被移除。

## 7. 错误反馈

无效连接不修改项目、不改变保存状态、不创建撤销历史，也不退出工具栏连线模式。

可见提示与 `aria-live="polite"` 使用同一份中文错误文案：

| 原因 | 提示 |
|---|---|
| 节点不存在 | 节点已发生变化，请重新选择 |
| 自连 | 节点不能连接到自身 |
| 重复连接 | 这两个节点已经连接 |
| 循环依赖 | 此连接会形成循环依赖 |
| 类型不兼容 | 这两种节点不能建立生成依赖 |

拖拽失败后清除临时拖线；工具栏失败后保留来源节点，方便用户重新选择目标。下一次成功、主动取消或重新进入连线模式时清除旧错误。

## 8. 键盘与可访问性

- “连线”工具是可切换按钮，使用 `aria-pressed` 表达激活状态。
- 工具栏连线模式支持 `Enter/Space` 选择来源和目标，支持 `Esc` 取消。
- 节点的输入与输出端口有可读名称，不只依赖位置或颜色区分。
- 每条连接可聚焦，并提供“来源标题 → 目标标题”的可读标签。
- 连接选中、合法目标、非法目标和来源变化同时使用形状、文字或图标反馈，不只改变颜色。
- 在 200% 页面缩放和 721×778 CSS 视口下，连接状态提示与删除操作必须可见、可聚焦、可点击，不与 AI 导演或节点主操作重叠。
- 节点列表替代视图继续按依赖深度排序；本轮不在列表中增加独立关系编辑器。

## 9. 验收与测试

### 9.1 规则单元测试

- 覆盖完整类型兼容矩阵。
- 覆盖节点不存在、自连、重复连接和循环依赖。
- 覆盖多个上游连接到同一目标。
- 覆盖载入旧项目时不删除不兼容既有连接。

### 9.2 Store 测试

- 合法创建与删除各只产生一个历史条目。
- 无效操作不改变项目引用、保存状态或历史。
- 创建和删除后正确标记目标与下游来源变化。
- 撤销、重做准确恢复连接和来源变化状态。
- 真实 IndexedDB 保存与刷新恢复连接。

### 9.3 组件与浏览器测试

- 端口拖拽创建合法连接。
- 工具栏依次点击与键盘 `Enter/Space` 创建相同连接。
- 不合法目标显示对应原因且不创建连接。
- `Esc`、空白点击和工具切换无副作用取消，并验证焦点返回。
- 鼠标与键盘均可选择和删除连接。
- 多上游连接可见且不改变时间线顺序。
- 200% 页面缩放下核心状态与删除操作可达。
- 完整流程控制台没有新增错误。

## 10. 明确不包含

本轮不实现：

- 节点分组和分组容器。
- 连线标签、端口命名和多端口语义。
- 自动布局或自动整理连接。
- 连接条件、分支逻辑或工作流执行引擎。
- 真实模型接入。
- 时间线或导出流程改造。
- 关系管理侧栏。

## 11. 完成标准

以下条件全部满足后，本功能才算完成：

1. 两种创建入口行为一致，并共用规则与 Store 提交路径。
2. 新连接严格遵守类型、重复、自连和循环限制。
3. 一个目标可稳定接收多个上游输入。
4. 创建、删除、撤销、重做、自动保存和刷新恢复全部可用。
5. 鼠标、键盘和 200% 页面缩放均能完成核心流程。
6. 无效操作无项目副作用，并提供具体、可读的错误原因。
7. 单元测试、组件测试、类型检查、生产构建和 Chromium 端到端测试全部通过。
