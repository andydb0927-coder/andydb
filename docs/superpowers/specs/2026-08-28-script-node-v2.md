# 脚本节点 v2：拆解、分镜与批量出图

## 范围与兼容

起点：`codex/platform-shell-phase` / `55bb93f`。保留旧脚本生成、章节编辑与所有已有节点行为；只增加可选字段，不更改 IndexedDB 表结构，不清用户数据。自动化仅使用 fixture，不调用真实服务、不触碰密钥。

## 数据与职责

- 脚本节点详情扩展章节下的 `scenes`、`characters`、`props`、`shots`。每镜保存景别、机位、运镜、提示词、角色 ID、结果资产 ID、任务状态与发送后的画布节点 ID。
- 两个隐藏工具 provider 复用现有豆包传输：剧本拆解、分镜生成。严格解析 JSON，拒绝缺字段、未知场景/角色引用、超限结果；不以演示结果兜底。
- 脚本执行器复用 GenerationQueue、ProviderRegistry、项目保存链；不在 React 组件内自行请求 API。逐镜调用现有 Seedream provider，单请求单图、串行执行；每镜立即保存版本、资产、历史和分镜结果。
- 脚本原文、模型选择与章节不能被图片任务覆盖。原有脚本生成不进入 v2 解析路径。
- 故事板视图和节点工作台读取同一份 `shots`；编辑、发送画布均回写源节点。

## 交互与安全

1. 脚本节点“AI拆解”打开工作台；填剧本，确认豆包调用与预计费用后拆解。
2. 显示章节/场景、角色与道具；“生成分镜故事板”基于已拆解场景生成可编辑镜头表。重新拆解/生成镜头表提示替换旧表，原资产与历史保留。
3. 选择闭区间与输出比例/清晰度，按 provider manifest 显示真实尺寸、单镜和总预计成本。确认后依次生成尚无成功结果的镜头。部分失败不中断已保存成果，显示失败原因；重试仅运行未成功镜头。
4. 任务期间禁用冲突编辑/重复提交，支持停止后续任务；切换项目或画布中止本轮，不将旧结果写入新画布。每镜保存失败时停止继续产生费用，保留内存结果并提示恢复保存。
5. 每张成功分镜“发送画布”创建图片节点，保留资产引用与提示词；重复点击定位已创建节点，不重复插入。
6. 主体库现有契约要求真实样本图。因此角色条目选择已上传/已生成图片后，“提取主体”复用已有视觉提取 provider → 主体库；没有图时明确禁用原因，不把文字描述冒充视觉提取。已提取角色可直接复用。
7. 选择角色参考图本身也持久化并参与分镜请求，不必先调用主体提取。更换样本图会解除旧主体关联，但不删除主体库原记录。
8. 冷启动遇到中断的脚本任务只标记取消，不自动重发请求；已完成结果保留，重试须再次确认费用。费用确认框关闭后焦点回到工作台内稳定控件，Escape 可继续退出。
9. 删除被引用的资产复用原有影响确认，同时清除分镜/角色的对应引用，允许缺图镜头重新生成。工作流 JSON 保留脚本字段并重映射资产与画布节点 ID；不迁移生成任务及主体库 ID，避免悬空关联。旧脚本没有 v2 可选字段仍可导入。

## TDD 与验收

- 合同：拆解/分镜 JSON、错误与取消、无配置禁用、请求体及来源 token 用量。
- 领域：区间/成本、引用传递、逐镜串行、部分失败保留、重复点击、资产/版本/历史持久化、项目隔离、旧脚本兼容。
- UI：工作台与故事板共用卡片、编辑、确认、禁用原因、721px 弹层可达。
- 附加边界：章节编辑后仍沿用原场景 ID；拒绝异常任务状态与坏引用 JSON；720×450 等效 200% 视口可完成确认、重试和关闭。
- E2E：fixture 拆解 → 分镜 → 串行出图（含失败和重试）→ 刷新恢复 → 主体库 → 发送画布。
- 门禁顺序：typecheck → test:run → build:mock → PLAYWRIGHT_OFFLINE_DIST=dist playwright；保留原有截图改动，提交推送后核验远程 SHA。
