# 无线画布 LibTV 功能域路线图与平台骨架设计规格

日期：2026-08-13

状态：已确认，进入实施

范围：以 LibTV 的功能域和操作关系为参考，完善无线画布的本地优先创作平台；不复制品牌、私有数据、会员价格或未验证的服务端能力。

## 1. 产品目标

无线画布要从单一无限画布扩展为完整的 AI 影视创作平台，同时继续把画布作为核心工作区。用户应能从平台首页进入项目，完成素材、模型、剧本、工作流、生成、时间线、导出、作品、协作与扩展能力的连续任务。

本路线图采用“功能域等价、交互原创、能力诚实”的原则：

- 对齐 LibTV 可观察到的页面层级、创作链路和任务入口；
- 保留无线画布现有的节点、依赖连线、生成队列、时间线和本地持久化；
- 真实 LibTV 写入、账号、支付、云协作等能力必须有明确门禁，不能用演示数据冒充；
- 每个阶段必须先写可执行验收，再用 TDD 完成，并独立提交。

## 3. 平台信息架构

```text
无线画布
├── 项目空间与平台首页 `/`
├── 创作画布 `/project/:projectId`
├── 成片预览与时间线 `/project/:projectId/preview`
├── 素材与历史 `/assets`
├── 工作流与模板 `/workflows`
├── 发现与作品 `/discover`
│   ├── 我的作品 `/discover/mine`
│   └── 作品详情 `/discover/:workId`
├── 模型能力 `/models`
├── Agent 技能 `/agents`
└── 本地工作区 `/account`
```

平台壳层使用统一全局导航。普通内容页显示完整导航；画布与时间线使用紧凑导航，优先保留工作区宽度。任何新增入口必须落到真实页面、真实本地数据或明确标注的能力边界。

## 4. 第 1 阶段：平台骨架

### 4.1 全局导航

- 保持既有路由和项目深链不变；
- 支持标准与工作区两种密度；
- 当前路由具有可感知的选中状态；
- 导航可收起，键盘与屏幕阅读器可操作；
- 页面采用路由级按需加载，并提供中文加载状态。

### 4.2 任务编排抽屉

新增全局“阶段任务”入口，用于呈现 13 个功能域的顺序、状态与下一步：

- 抽屉桌面宽度约 340px；默认收起；
- 展开时作为平台网格中的独立列推动内容，不覆盖画布节点、连线、浮动工具或时间线控件；
- 标准页与工作区页均可打开；工作区打开后画布可用宽度随壳层变量同步；
- 抽屉包含总进度、当前阶段、13 阶段列表、状态切换与目标页面入口；
- `Escape` 关闭后焦点返回触发按钮；
- 小于 900px 时使用受限宽度的底部区域或纵向流，仍不得覆盖画布主操作；
- 关闭按钮、阶段操作和目标链接都有明确可访问名称。

### 4.3 本地进度持久化

任务进度是明确要求的设备本地编排状态，因此使用版本化 `localStorage`，不作为云端或跨设备真相源：

```ts
type PlatformTaskStatus = 'pending' | 'in-progress' | 'completed'

interface PlatformTaskProgressSnapshot {
  version: 1
  updatedAt: string
  statuses: Record<PlatformTaskId, PlatformTaskStatus>
}
```

- 存储键：`wireless-canvas:platform-task-progress:v1`；
- 读取失败、结构损坏或未知阶段时回退到内置默认值；
- 只保存已知阶段，防止旧版本污染；
- 跨标签页 `storage` 事件刷新当前视图；
- 抽屉开合属于瞬时布局偏好，默认始终收起，不跨会话强制展开。

### 4.4 初始状态

初始状态依据当前仓库已验证能力，而不是竞品宣称：已完成的平台域标记为完成；仍需要真实账号、云发布或实时协作的域标记为进行中。用户可以在本设备调整状态，后续阶段提交时同步默认目录。

## 5. 交互与视觉要求

- 继续使用现有深色、紫色强调和紧凑编辑器视觉；
- 抽屉不使用全屏遮罩，不引入模态阻断；
- 桌面展开后宽度为 `340px`，主内容 `min-width: 0`，避免横向溢出；
- 阶段状态不仅依靠颜色，还显示文字和图标；
- 动画仅用于宽度、透明度和位移，尊重 `prefers-reduced-motion`；
- 320px 起可访问，44px 触控目标，焦点环清晰。

## 6. 数据与安全边界

- 不把 localStorage 进度解释为账号、计费或团队数据；
- 不自动触发 LibTV 写入、生成消费、发布、分享或外部消息；
- 静态托管下 LibTV 与 workspace CLI 服务端桥接不可用时应明确降级；
- 不读取、修改、暂存或提交 `audit-2026-08-06/`；
- 后续若接入云账户和真实任务状态，必须迁移到服务端持久化并保留版本迁移。

## 7. 验收标准

1. 所有平台页都能看到统一导航与“阶段任务”入口。
2. 首次加载抽屉关闭；打开后计算宽度约 340px，且画布节点主操作不被覆盖。
3. 修改阶段状态后刷新仍保留；损坏存储值可安全恢复。
4. 在工作区打开和关闭抽屉时，画布顶栏与视口边界同步，不发生双重偏移。
5. 键盘可打开、操作并用 Escape 关闭，焦点返回触发按钮。
6. 路由深链、项目创建、画布、预览、素材、工作流、作品、模型、Agent 与工作区页面保持可用。
7. 每阶段必须通过聚焦 Vitest、全量 Vitest、`npm run typecheck`、`npm run build` 和 `git diff --check` 后独立提交。

## 8. 非目标

- 不在第 1 阶段新增真实登录、付费、云同步、实时协作或生产级视频转码；
- 不复制 LibTV 的商标、私有素材、用户作品、积分余额或会员价格；
- 不把本地演示能力描述为在线生产服务；
- 不在当前分支自动合并 `main` 或公开部署。
