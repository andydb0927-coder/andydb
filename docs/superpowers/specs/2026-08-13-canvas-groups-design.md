# 无线画布 LibTV 功能域第 4 阶段：画布分组与工作流设计规格

日期：2026-08-13

状态：已确认，进入实施

范围：在既有无限画布、节点、连线、依赖、撤销和工作流基础上，补齐当前工具栏明确缺失的节点分组能力；不改动生成模型、素材、时间线或外部服务。

## 1. 参照与基线

LibTV 画布采用工作流/故事板切换、节点式无限画布和紧凑工具入口。当前无线画布已具备：

- 文本、图片、分镜、视频与结构化创作卡节点；
- 端口拖拽、工具栏连线、依赖校验、连线隐藏与删除；
- 框选、多选批量拖动、节点列表、依赖影响确认；
- 撤销/重做、自动保存、工作流串行/并行运行和恢复；
- 工具栏“分组”仍明确显示“将在后续版本提供”。

本阶段以真实补齐该占位能力为目标。分组是画布组织元数据，不改变生成依赖、执行顺序、时间线或节点坐标语义。

## 2. 选定方案

1. 选中至少两个节点后启用“分组”；
2. 创建分组后显示包围成员节点的视觉框和自动名称；
3. 点击分组标题选中全部成员，复用现有多选批量拖动；
4. 当当前选择恰好等于某分组成员时，工具栏切换为“取消分组”；
5. 分组/取消分组各形成一个撤销历史项并触发自动保存；
6. 节点可重新组合：新分组会从旧分组移出所选节点，并移除不足两个成员的旧分组；
7. 删除节点会同步移出分组，并清理不足两个成员的分组；
8. 老项目没有 `groups` 字段时按空数组处理，不做破坏性迁移。

## 3. 项目模型

```ts
interface CanvasGroup {
  id: string
  title: string
  nodeIds: string[]
  createdAt: string
  updatedAt: string
}

interface Project {
  // existing fields...
  groups?: CanvasGroup[]
}
```

- 新项目显式初始化 `groups: []`；
- 既有项目和导入包保持兼容，读取时使用 `project.groups ?? []`；
- 分组 ID 使用本地 UUID；
- 默认名称按现存最大编号递增，例如“分组 01”；
- 成员 ID 去重并保持项目节点顺序，避免选择顺序导致不稳定持久化。

## 4. 领域规则

### 4.1 创建分组

- 过滤不存在的节点 ID；
- 少于两个有效节点时不产生更改和历史；
- 从已有分组移除所选成员；
- 清理剩余成员少于两个的旧分组；
- 新增分组并更新项目时间戳；
- 单次操作只产生一个 undo 基线。

### 4.2 取消分组

- 只按现存分组 ID 删除；
- 不存在的 ID 不产生更改和历史；
- 不删除节点、连线、时间线、资产或工作流记录。

### 4.3 删除节点

- 保留既有下游影响、连线、时间线和任务清理规则；
- 同时从所有分组移除该节点；
- 清理不足两个成员的分组。

## 5. 视觉分组

- 在 React Flow 的 viewport portal 内绘制分组框，使缩放和平移与节点一致；
- 边界来自成员节点坐标和已测量尺寸；未测量时使用安全默认尺寸；
- 上、下、左右保留固定 flow-space 内边距；
- 分组容器本身不拦截节点、连线或框选；
- 标题按钮和取消按钮可接收指针与键盘操作；
- 点击标题后整组节点被选中，主节点确定为组内最后一个有效成员；
- 分组框使用弱背景和虚线边界，不冒充生成依赖。

## 6. 工具栏与反馈

- 未选满两个节点时“分组”禁用，标题说明需要至少两个节点；
- 选中两个或更多节点时启用“分组”；
- 精确选中一个现存组时显示“取消分组”；
- 草稿、编辑弹层或项目加载期间继续禁用；
- 成功后使用画布状态提示“已创建分组”或“已取消分组”；
- 不引入新的持久模式，操作完成后仍处于选择工具。

## 7. 性能与兼容

- 每次渲染用节点 Map 计算分组边界，复杂度 O(V + 分组成员数)；
- 不扫描依赖边，不改变已有 O(V+E) 依赖处理；
- 拖动中沿用现有 drag preview，分组边界随预览节点位置刷新；
- 分组元数据随项目 Dexie JSON 原子保存，项目包自然包含该字段；
- 不新增数据库表或数据库版本。

## 8. 可访问性

- 分组视觉区域使用命名 `group`；
- 标题按钮命名为“选择分组：名称”；
- 取消按钮命名为“取消分组：名称”；
- 工具栏状态通过按钮名称、disabled 与 title 表达，不只靠颜色；
- 成功反馈使用现有 `role=status`；
- 组容器不进入画布节点删除和连线逻辑。

## 9. 验收标准

1. 工具栏分组按钮不再是永久占位。
2. 少于两个节点时禁用，两个及以上节点时可创建。
3. 分组持久存在于项目数据，视觉框覆盖成员并随拖动更新。
4. 点击组标题选择全部成员，现有批量拖动仍只产生一个历史项。
5. 取消分组、undo、redo 和自动保存工作正常。
6. 删除/重新组合节点不会留下单成员或孤立分组。
7. 分组不改变 edges、timeline、jobs 和 workflow 执行顺序。
8. 第 4 阶段完成后路线图推进到第 5 阶段。
9. 聚焦 Vitest、全量 Vitest、typecheck、build、lint 与 diff-check 全部通过后独立提交。

## 10. 非目标

- 嵌套分组、分组重命名、颜色编辑、锁定和权限；
- 把成员坐标改为 parent-relative 坐标；
- 分组整体独立拖拽手柄；
- 更改生成依赖、工作流调度或真实模型请求；
- 公开部署或合并主分支。
