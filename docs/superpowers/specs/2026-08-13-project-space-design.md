# 无线画布 LibTV 功能域第 3 阶段：项目空间设计规格

日期：2026-08-13

状态：已确认，进入实施

范围：把平台首页与项目目录分离，新增 `/projects` 项目空间，提供全部项目、搜索、排序、本地文件夹和项目分类；不新增未经证据支持的破坏性管理、云同步或外部写入。

## 1. 参照证据

已登录 LibTV 的只读核对显示：

- 全局导航把首页与项目作为两个独立入口；
- 项目页包含“全部项目”“新建文件夹”“开始创作”；
- 项目以卡片形式展示，并呈现更新时间；
- 首页继续承担创作启动和最近项目入口。

本阶段只复刻这些稳定的信息架构与本地可实现能力，不复制用户私有项目、身份、余额或未实际验证的卡片菜单行为。项目删除、批量移动、回收站、云团队目录和共享权限不在本阶段伪造。

## 2. 当前基线与问题

当前 `/` 同时承担平台首页、创作启动与最近项目，平台导航却把它命名为“项目空间”。项目仓储只支持保存、读取和最近列表，缺少：

- 独立的全部项目目录；
- 搜索和可预测排序；
- 用户自建文件夹；
- 项目到文件夹的持久分类；
- 首页和项目空间之间清晰的导航边界。

## 3. 选定方案

1. `/` 保持平台首页与创作启动页；
2. 新增 `/projects` 作为独立项目空间；
3. 平台“项目空间”导航改指向 `/projects`；
4. 项目空间读取全部本地 Dexie 项目，并提供标题/创作意图搜索；
5. 提供“最近更新”和“名称排序”；
6. 支持创建本地文件夹，并把项目归入某文件夹或移回“未归类”；
7. 文件夹和项目位置写入同一 Dexie 数据库的独立表，不修改项目内容；
8. 首页最近项目和画布打开路径保持兼容。

## 4. 数据模型

```ts
interface ProjectFolder {
  id: string
  name: string
  normalizedName: string
  createdAt: string
  updatedAt: string
}

interface ProjectLocation {
  projectId: string
  folderId?: string
  updatedAt: string
}
```

- 数据库从 v8 升级到 v9；
- `projectFolders` 以 `id` 为主键，`normalizedName` 唯一；
- `projectLocations` 以 `projectId` 为主键，一个项目最多属于一个文件夹；
- 文件夹名称去首尾空格，并按 Unicode 小写值做本地唯一判断；
- 移动项目前验证项目存在；指定文件夹时同时验证文件夹存在；
- 所有校验和写入在 Dexie 事务中完成；
- 失去对应项目的孤立位置记录不在界面展示。

## 5. 项目空间界面

### 5.1 页面头部

- 标题“全部项目”和本地项目总数；
- “开始创作”返回 `/`；
- 明确当前为本地设备项目目录。

### 5.2 文件夹导航

- 固定“全部项目”“未归类”；
- 展示用户创建的文件夹与实时项目数量；
- “新建文件夹”使用带标签的原生表单；
- 重名、空名和存储错误以状态文本呈现，不丢失已加载项目。

### 5.3 搜索与排序

- 搜索标题和创作意图，忽略大小写与首尾空格；
- 排序支持“最近更新”和“名称”；
- 过滤结果为空时显示与当前查询/文件夹相关的空状态。

### 5.4 项目卡片

- 展示项目标题、意图、更新时间、节点数和素材数；
- 主操作“打开项目”进入 `/project/:projectId`；
- 文件夹下拉框即时持久化项目位置；
- 分类失败时保留原分类，并给出错误反馈。

## 6. 状态与并发边界

- 初次加载同时读取项目、文件夹和项目位置；
- 使用请求序号和卸载标记，避免过期异步结果覆盖新状态；
- 创建文件夹与移动项目期间禁用对应控件，防止重复提交；
- 成功写入后从仓储重新读取，避免界面自造数据库状态；
- 数据库读取失败显示重试入口，不伪造空项目成功态。

## 7. 可访问性与响应式

- 文件夹为命名导航，当前筛选使用 `aria-current`；
- 搜索、排序、文件夹创建和项目分类均使用原生可聚焦控件；
- 状态反馈使用 `role=status` 或 `role=alert`；
- 卡片在窄屏改为单列，操作区不覆盖标题和元数据；
- 信息不只依赖颜色表达。

## 8. 验收标准

1. `/projects` 可从全局导航访问，且与 `/` 首页职责分离。
2. 页面显示全部本地项目并可打开画布。
3. 搜索标题/意图与两种排序工作正常。
4. 文件夹可创建且刷新后仍存在；空名和大小写重复被拒绝。
5. 项目分类可持久化，移回未归类后刷新保持。
6. 不存在的项目或文件夹不会产生无效位置记录。
7. 原首页创建、最近项目和其他数据库迁移回归保持通过。
8. 任务编排推进为第 3 阶段完成、第 4 阶段进行中。
9. 聚焦 Vitest、全量 Vitest、typecheck、build 和 diff-check 通过后独立提交。

## 9. 非目标

- 项目删除、回收站、重命名、批量选择和批量移动；
- 云端账号、团队文件夹、多人权限和远端同步；
- 推断或复制 LibTV 未验证的项目卡片更多菜单；
- 第 4 阶段的画布与工作流扩展；
- 公开部署或合并主分支。
