# 出海转绘批4：交付契约与检查边界

日期：2026-09-10。来源：客户《审核交付验收标准.pdf》（26页，主要为第12–17、22–24页）。本批是本地交付检查/清单归档，不是视频打包转码器或飞书上传器。

## 1. 客户硬指标与检查覆盖

| 领域 | 客户要求 | 当前自动检查 | 外部工具/人工核验接口 |
|---|---|---|---|
| 视频 | 1080×1920竖版；正方形像素；H.264 MP4；码率≥25Mbps；25或30fps；SDR Rec709 | runner `file-spec`校验人工提供的分辨率、编码、容器、码率、帧率、Rec709字段 | ffprobe读取实际流信息、像素宽高比、色彩传递等；浏览器不运行ffprobe，SDR必须外部确认 |
| 声道 | 双声道且两侧都有声音 | `audio-channels`检查channels=2 | 仅声道数不能证明两侧有声；需逐声道波形/实际试听 |
| 分层音量 | 人声-1~-12dB；音效-30~-1dB；背景音乐-18~-30dB | 未实现分轨信号分析 | 保存分轨检测报告引用。比较区间写作人声[-12,-1]、音效[-30,-1]、BGM[-30,-18]；不得擅自解释成LUFS |
| 音频完整性 | 从头至尾完整音轨，无爆音/过载/截断；全剧波动≤±3dB | `audio-volume`按测量基准校验输入偏差绝对值≤3 | 全片/全剧波形与响度分析、试听；单个输入数值不证明整片完整性 |
| 口型 | 交付要求≤0.3s | `lip-sync`检查已提供的最大绝对时间差；0.3–0.5为WARN | 交付比自审严格：WARN也阻塞。实际口型识别/精修未实现，逐镜测量需人工或独立服务 |
| 字幕字体 | 英/西/葡TikTokSansText-Bold，日语Noto_Sans_JP；全剧一致且有商业版权 | 不识别成片字体/版权 | 客户PDF允许其他获商用授权字体，但本项目默认按指定字体；替代需客户确认，不默许 |
| 字幕外观 | 白字，黑描边5，黑阴影透明度65%，字号10，行间距4；1–3行居中安全框 | `subtitle-layout`校验1–3行、输入框位置；`subtitle-overlap`校验同集字幕区间不交叠 | 5/10/4为剪映参数，不等于网页CSS像素。安全框5%–95%只是项目默认，不是PDF图示的精确测量；须叠加客户安全框人工验成片居中/遮挡 |
| 本地化文字 | 无中文残留；数字遵循语种规则 | `localized-chinese`、`localized-numbers`扫描本地化文本域 | 不含烧录文字OCR，不证明翻译语义。西语电话/官方编号须明确上下文；英语/葡语数字10边界仍待确认 |
| 海报 | 两版3:4=1080×1440、9:16=1080×1920，JPEG≤10MB，主体一致；不可简单拉伸 | 未自动检查 | 外部图像元数据与尺寸检查；逐集核对9:16压首帧且含EP集号，完整剧名、安全框。3:4另贴交付表；制作第一集之前贴好审查 |
| 集号 | EP001三位数、1–N连续、无缺集/重号 | `episode-name`、`episode-sequence`；从工作台实际镜头集号去重排序，结合人工声明全剧总集数校验，不信任可伪造的元数据集名 | 实际文件名/剧集完整性仍须对照客户总表；一个镜头不代表完整一集 |
| 文件夹 | `AI承制剧/AI转绘剧-公司名-剧名（中文加英文）-语言` | 未检查磁盘目录 | 开头两类为二选一，不创建含斜线的单目录；不写语言默认英语，其他语种标注。PDF同时要求“网盘里只能有视频文件，不要有任何文件夹”和“夹层不得超过两层”；保守执行交付视频目录平铺，外围目录层级与客户确认 |
| 飞书 | 第一列原片按集号一集一行；第二列只填甲方意见，不能上传文件或覆盖；第三列放收到意见后的修改版，禁止覆盖第一列 | 不连接飞书 | 全部内审通过前禁止对甲方文档任何操作。只有第二列无意见且内审确认需自主修正时，可二次确认第二列为空后覆盖第一列；不得自动套用例外 |
| 修改 | 各节点最多3次，验收后才能向下制作；版本不得覆盖 | runner `revision-count` + 批1状态机；满3禁用请求返修并显示“已达修改上限，请走人工复核” | 本地local-reviewer不是已认证客户身份；清单不是客户验收或签收 |

## 2. 交付门禁

入口：工作台“交付包检查与导出”或已通过镜头的“交付”。范围为当前镜头/当前整集。整集包含该集所有镜头，不按“已通过”过滤。

1. 所选范围非空且每镜为“已通过”；已交付记录只能从台账重新下载原清单。
2. 最新生成版本、批准版本、自审表版本必须一致；当前自审表和批准时存档的确认表签名必须与现有方案、资料、检测数据、镜头清单一致。
3. 每镜重新运行批3的全部11个自动子项，必须全部PASS。FAIL与WARN（缺数据、未配置语种规则、口型0.3–0.5s等）均红色阻塞。32条完整标准保留原始WARN，只有绑定当前版本的全项人工确认表作为依据，不改写为自动PASS。
4. 全剧集号取自实际工作台数据；人工输入预期总集数，必须1–N连续且数量一致。清单仅声明选定交付范围，不把单镜头导出冒充整集成片。
5. 登记外部检测报告、实际交付文件引用、核验人，完成六组外部核验（文件、分层声音、口型、字幕、海报、交接）。保存时间与当前数据签名由仓储生成，不能由表单伪造。报告未被系统联网取证，也未签名认证，必须明示“人工登记”。
6. 保存层重做相同门禁，旧`deliver`路径不能绕过；整集清单和状态流转在同一IndexedDB事务完成，乐观锁阻止重复点击/过期页面写入。任一镜头失败，整批不写。

对无台词/无字幕等确实不适用项，当前没有经客户批准的豁免协议：缺数据仍阻塞，走人工复核，不填虚假0或占位字幕绕过。方案或剧集结构变更导致确认失效时，需返修后自审；已到3次上限保留原记录并人工复核，不擅自重置次数。

## 3. 导出与版本记录

独立命名空间`dubbing.delivery`，schemaVersion=1。`DubbingWorkspace.deliveryPackages?`与`DubbingWorkbenchShot.deliveryEvidence?`为可选字段，旧数据库不迁移、不清空、不改画布主结构。

交付清单包含：清单ID/项目ID/时间/范围/交付引用/全剧预期集数/实际集名；每镜镜号、versionId、assetIds、自审记录ID与确认表全文、全部原始检查结果、外部报告与文件引用/核验人/时间、revisionCount、交付引用。

仅导出JSON清单，**不包含MP4/JPEG二进制，不自动下载媒体、不压ZIP、不转码、不发飞书**。自审表和报告是深拷贝快照，历史只追加；刷新可在“交付版本台账”重新下载。下载失败不会丢失已存清单，并有中文重试提示。

## 4. 外部测量适配接口（预留，未接工具）

- 测量适配器输出`DubbingQaEvidence`交给`saveQaEvidence`，拒绝调用方注入PASS等结果字段；当前通过“填写检测数据”手工粘贴JSON。
- ffprobe适配器未来输出width/height/codec/container/bitrateMbps/fps/colorSpace/channels；SDR、实际双声道有声、分层音量、海报与字体暂由外部报告说明，不冒充已实现检测器。
- `DubbingExternalEvidenceInput`字段：`reportReference`、`fileReference`、`reviewer`、`checkedIds`。系统追加`at`与`signature`。全套六组人工核验不能替代自动FAIL/WARN。
- 无真实API调用、无新Key、无软件安装、无飞书写入；唇形精修、客户样片验收及权利认证不在本批可承诺范围。

## 5. 验证与回滚

TDD覆盖缺证、WARN/FAIL、过期签名、集号连续性、整集原子提交、旧交付入口、乐观锁与恢复；浏览器覆盖送审→三轮返修→完整自审→外部依据→整集清单下载→刷新及三视口/Esc。

实现可整体撤回本批代码提交；数据字段是向后兼容新增，旧代码忽略新字段，但不可让旧交付入口在已有新数据上继续不受检查地交付。回滚不删除任何IndexedDB用户资料；归档文件可独立保留。
