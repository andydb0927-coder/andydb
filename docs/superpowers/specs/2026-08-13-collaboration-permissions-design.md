# 无线画布 LibTV 功能域第 12 阶段：协作、权限与会员设计规格

日期：2026-08-13

状态：已确认，进入实施

## 1. 基线与缺口

平台已有本地所有者/编辑者/只读成员、节点与片段评论、项目包、会员状态机、高级导出和批量工作流门禁。但角色权限只是文本，评论只能新增/解决，项目包对协作记录只做浅层结构校验。

## 2. 设计方案

### 2.1 统一角色权限

- 增加纯函数权限矩阵，作为所有者、编辑者、只读三种角色的唯一本地判定源；
- 能力包括编辑项目、发表评论、解决评论、管理成员和导出项目包；
- `/account` 显示可读的角色权限矩阵。

### 2.2 可追踪评论变更

- 本机所有者可编辑或删除评论；
- 编辑和删除必须携带当前 `updatedAt` 版本；
- 仓库事务内发现版本不一致时拒绝覆盖，返回固定的“已被其他操作更新”提示；
- UI 编辑草稿可取消，成功后更新本地列表，失败时不泄露底层数据库信息。

### 2.3 项目包输入强校验

- 校验协作者 ID、项目 ID、姓名、角色和时间字段；
- 校验评论 ID、项目 ID、目标类型/ID、正文、作者、状态和时间字段；
- 拒绝未知枚举值、空字段和跨项目协作记录。

## 3. 会员与产品边界

- 会员仍为 Dexie 本地模拟，不调用真实支付、订阅或积分接口；
- 权限矩阵是本地交互合同，不声称已实现服务端强制授权；
- 不增加在线状态、邀请邮件、即时通知或跨设备同步。

## 4. 验收标准

1. 三种角色的能力矩阵有纯函数测试并在账户页可读。
2. 评论可编辑、取消编辑和删除。
3. 过期版本的编辑/删除被原子拒绝。
4. 项目包拒绝非法角色、评论状态和空关键字段。
5. 第 12 阶段完成后路线图推进到第 13 阶段。
6. 聚焦/全量 Vitest、typecheck、build、Oxlint 和 diff-check 通过后独立提交。
