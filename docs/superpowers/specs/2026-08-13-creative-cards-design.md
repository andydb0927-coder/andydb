# 无线画布步骤 2：剧本、角色与世界观卡片设计规格

日期：2026-08-13  
状态：已批准，依据用户“不询问我，直接完成”执行  
范围：在现有项目画布中增加可编辑、可连线、可引用素材库图片的剧本卡、角色卡和世界观卡。

## 1. 当前基线

当前应用已具备：

- 可持久化的 `Project` / `CanvasNode` / `Asset` / `NodeVersion` 模型；
- React Flow 画布、拖拽、选中、删除、撤销/重做和键盘操作；
- 有向无环的节点连线与类型矩阵；
- 素材库、项目素材同步、生成结果归档与 IndexedDB 持久化；
- 文本、图片、分镜、视频节点的画布内新建流程。

现有 `character` 节点表示“角色参考图”，并不是结构化角色资料。本阶段不改写它，而是新增 `character-card`，确保旧项目和已有生成链路不受影响。

## 2. 目标与非目标

### 2.1 目标

1. 画布工具栏可新建剧本卡、角色卡、世界观卡。
2. 创建和编辑都使用明确的结构化字段，不把多个字段压成一段不可恢复的 prompt。
3. 三类卡片可相互建立有向关联，仍拒绝自连、重复连线和循环。
4. 三类卡片都可选择素材库中的图片；项目只保存素材 ID 关系，不重复存储图片数据。
5. 卡片编辑产生新 `NodeVersion`，保留现有版本、撤销/重做、下游变更标记和自动保存语义。
6. 卡片节点在画布和节点列表中都有可识别类型、摘要和编辑入口。

### 2.2 非目标

- 不实现长篇剧本的分页、场次排序或 Final Draft 导入导出。
- 不实现多图画廊、人物三视图或自动服化道连续性检查。
- 不在本阶段触发 LibTV 或其它生成提供方。
- 不引入云端协作、评论、权限或会员能力。

## 3. 领域模型

`NodeKind` 新增：

```ts
type CreativeCardKind = 'script' | 'character-card' | 'worldview'
```

`CanvasNode` 新增可选字段 `card?: CreativeCard` 以保持旧数据可读。新卡片必须使 `node.kind === node.card.kind`。

```ts
type CreativeCard =
  | {
      kind: 'script'
      scenes: string
      dialogue: string
      shotNotes: string
      imageAssetId?: string
    }
  | {
      kind: 'character-card'
      name: string
      appearance: string
      wardrobe: string
      relationships: string
      imageAssetId?: string
    }
  | {
      kind: 'worldview'
      background: string
      artStyle: string
      rules: string
      imageAssetId?: string
    }
```

图片引用同时写入当前版本的 `assetId`，以复用现有节点素材解析、预览和历史语义。`card.imageAssetId` 是当前结构化状态，`NodeVersion.assetId` 是该版本快照的引用。

## 4. 字段与校验

| 卡片 | 必填 | 可选 | 默认标题 |
| --- | --- | --- | --- |
| 剧本卡 | 标题、分场 | 对白、镜头备注、引用图 | `剧本卡 01` |
| 角色卡 | 标题、姓名、外貌锚点 | 服化道、关系、引用图 | `角色卡 01` |
| 世界观卡 | 标题、背景、美术风格 | 规则、引用图 | `世界观卡 01` |

标题去除首尾空白后最长 40 字符；每个文本字段去除首尾空白后最长 2,000 字符。错误必须关联到对应原生表单控件。

## 5. 连线规则

三类卡片之间允许任意方向的单向连线，但全局 DAG 规则仍禁止循环。三类卡片均可连向 `storyboard` 和 `video`，使其成为后续生成的上游语义依赖。

本阶段不改变旧节点的连线矩阵，也不让分镜/视频反向修改卡片。

## 6. 创建与编辑交互

1. 工具栏增加“剧本卡”、“角色卡”、“世界观卡”。
2. 选择工具后点击画布，在点击位置打开结构化编辑器。
3. 编辑器自动读取素材库，只展示图片记录；读取失败显示警报，但不阻止创建无图卡片。
4. 节点选中后显示“编辑卡片”，节点列表也使用同一入口。
5. 新建成功后选中并聚焦新节点；编辑取消或保存后把焦点返回原触发位置，若触发位置已卸载则返回画布节点。
6. `Escape` 取消，`Command/Ctrl + Enter` 保存，初始焦点在标题输入框。

## 7. 版本、持久化与素材

- 创建卡片产生第一个版本；编辑产生新版本并切换 `activeVersionId`。
- 版本 `prompt` 是按固定字段顺序生成的可读摘要，为后续生成提供稳定输入；结构化字段仍以 `card` 为权威数据。
- 选择素材库图片时，若项目尚未引用该素材，则将同一素材记录转为 `Project.assets` 快照；已存在时不复制。
- 撤销/重做、自动保存、刷新后恢复和素材库去重仍使用现有 ProjectStore / ProjectRepository 流程。
- 旧项目没有 `card` 字段时仍可正常渲染。

## 8. 可访问性与响应式

- 编辑器使用命名 `dialog`，字段有可见 label，错误使用 `role="alert"`。
- 素材加载使用 `role="status"`，读取失败使用去敏后固定文案。
- 卡片节点保留可聚焦的选中按钮和可键盘触发的连线端口。
- 面板在 640px 宽度下改为单列并限制最大高度，操作按钮仍可见。

## 9. 验收边界

自动化必须证明：

1. 三类领域校验、默认标题、版本摘要和图片去重正确。
2. 创建/编辑面板的字段、键盘和焦点行为可验证。
3. 三类卡片两两可连，循环、重复与不兼容连线仍被拒绝。
4. 画布可新建三类卡、编辑、选图、撤销/重做并持久化。
5. 真实 Chromium 从导入素材到创建三卡、连线、编辑、刷新和回到素材页完成关键路径，控制台无错误。
6. 现有 `/`、`/project/:projectId`、`/project/:projectId/preview`、生成、连线、素材、导出和键盘回归全部通过。
