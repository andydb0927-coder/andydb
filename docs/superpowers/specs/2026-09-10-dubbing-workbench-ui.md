# 出海转绘批 2：转绘工作台 UI

## 1. 范围与入口

基于批 1 的 `dubbing.shot`、`dubbing.localization`、`dubbing.qa` 领域契约。项目空间新增「出海转绘」入口，页面路由 `/dubbing`，支持 `projectId` 与 `shotId` 查询参数；链接由现有路由器处理部署子路径。

本批是已有生成结果的**本地送审工作台**，不新增生成 API，不触发收费请求、不自动通过审核、不上传交付文件。

## 2. 页面与交互

| 区域 | 内容与操作 |
| --- | --- |
| 左栏：剧集与镜头 | 按 EP001 三位集号分组；镜号、原片起止时间码、台词摘要、五态徽章、返修次数、查看按钮。紧凑镜头行保留表格语义，在 1024px 三栏内直接可见状态与操作。 |
| 中栏：详情与审核 | 双语台词、景别机位、原片引用、结果及引用资产预览、生成版本、只追加返修记录、自审与交付记录。长内容在栏内滚动。 |
| 右栏：本地化与 QA | 语种、全剧唯一姓名映射、十二类元素替换、字幕/花字/特殊规则、数字规则摘要；按九大类展示 32 项客户 PDF 验收标准。 |
| 编辑面板 | 本地化方案、镜头资料、返修意见与 QA 标准、交付引用；支持键盘焦点约束、Esc 取消和触发按钮焦点回归。保存中暂不允许关闭以免误认为取消成功。 |

### 按状态提供操作

- 待生成 / 待返修：有待提交资产时可「提交生成」；允许编辑当前镜头资料，无资产时显示返回画布补充结果提示。
- 「提交生成」沿用用户指定按钮名，实际含义为**提交已有生成结果进入待自审**。按钮附近明确提示不发起 API 请求。
- 待自审：QA 勾选与当前版本绑定，所有 P0 人工确认符合或不适用后可「标记自审通过」。P1/P2 保留供人工核对，本批不虚构客户未定义的累计阻断阈值。
- 待自审 / 已通过：可「请求返修」，必须填写意见并至少选择一个 QA 标准。最多三次，第四次按钮禁用并展示中文原因。
- 已通过：可「交付」，需登记交付包名称或引用；只表示本地状态记录，不代表上传或客户签收。
- 新返修资产提交后清空本版本 QA 勾选；历史生成版本、意见及自审证据只追加、不覆盖。

## 3. 画布互通

1. 节点右键「送审到工作台」；节点无结果时禁用并给出原因。
2. 生成历史卡片「送审到工作台」；仅成功且结果资产仍在的任务可用。
3. 新镜头填写原片资产 ID 或外部素材编号、原片时间码、集号镜号、双语台词和机位。**原片引用与生成结果分开**，不将生成时长或生成图片冒充原片。
4. 待返修镜头可接收另一条已有结果，提交为新版本。同项目的同节点 + 同资产重复送审返回原记录，避免重复建镜；同一资产不能作为另一轮返修结果重新提交。
5. 成功后提供「打开工作台」链接，由用户主动切换页面，避免送审完成直接打断画布操作。

`dubbing-canvas-adapter.ts` 只读取项目快照；不写入或扩展 `NodeKind`、`Asset`、`Project`，不改变原画布节点/资产/历史数据。

## 4. 存储与异常

- 新数据库：`wireless-canvas-dubbing-v1`，版本 1，`workspaces` 表以 `projectId` 为主键。
- 每个工作台包含镜头领域记录、待提交来源、资产快照、本版本 QA、自审历史及本地化方案。保持独立 `dubbing.workspace` 命名空间。
- 写操作使用 IndexedDB 事务；审核操作带 `version` 乐观锁。并发冲突提示刷新重试，不覆盖另一处更新。
- 界面写入设互斥锁，避免连续点击重复提交。QA 点击立即显示，保存失败恢复原勾选并显示错误，不吞保存异常。
- 读取失败有中文重试入口；无项目/无镜头/失效项目分别展示空态或错误；项目切换使用独立组件状态，避免混入上一项目记录。
- 引用临时 `blob:` 地址的结果拒绝送审；已有 HTTPS 地址可能过期，预览失败保留资产引用并明确提示。对历史结果 URL 的永久存储不在本批范围。
- 数据仅保存在当前浏览器。不同浏览器、清理站点数据、云端账号不会自动同步工作台。本批不接入云端工作台仓储。

## 5. 文件边界

- `dubbing-workbench-model.ts`：UI 持久化封装类型，不修改批 1 领域类型。
- `dubbing-workbench-repository.ts`：独立仓储、事务、乐观锁、调用既有审核状态机。
- `DubbingWorkbenchPage.tsx`：项目选择、读取/保存协调。
- `DubbingWorkbenchPanels.tsx`：镜头列表、详情、方案与 QA 展示。
- `DubbingIntakeDialog.tsx`、`DubbingPlanEditor.tsx`、`DubbingReviewDialogs.tsx`：独立表单。
- `DubbingDialog.tsx`：复用平台已有 `ConfirmDialog`，不另造全局弹层状态机。

## 6. 验证与回滚

先保留缺模块/送审入口/QA 点击反馈/原片引用的失败测试，再实现与修复。覆盖状态机按钮、三次返修上限、版本 QA 绑定、送审幂等、并发写冲突、姓名冲突、原片时间码、项目隔离、错误反馈和 Esc。

Playwright 使用隔离浏览器与 fixture；覆盖节点送审→三轮历史返修→P0 核对→通过→交付→刷新；以及方案编辑、项目空间入口、1440/1280/1024 三栏和焦点恢复。所有新测试无需真实供应商请求。

完整门禁结果与截图见 `docs/qa/dubbing-workbench-acceptance.md`。回滚时撤销本批代码提交即可，原项目数据未迁移；独立工作台数据库保留，不能为了回滚删除用户资料。
