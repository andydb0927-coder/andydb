# 无线画布 LibTV 功能域复刻：第 1 阶段平台骨架设计规格

日期：2026-08-11

状态：已确认，待实施

范围：平台级导航与真实信息架构；不接入真实生成、会员、协作或社区写入。

## 1. 目标

在不改变现有无限画布、节点、依赖连线、预览、导出、本地持久化与键盘可访问性的前提下，把无线画布从单一项目入口扩展为可持续生长的创作平台。

第 1 阶段交付的是一个可验证的平台骨架：用户可以在统一的应用框架中进入项目空间、继续创作画布、审阅已保存素材与版本历史、选用可执行的创作配方、浏览可打开的示例作品、理解当前模型能力边界，以及查看本地工作区状态。

## 2. 只读调研结论

截至本规格编写时，LibTV 的公开入口包含：首页、画布创作、Agent、精选作品与创作者活动。已登录可见的界面还包含最近项目、Skills 目录与收藏、团队入口、积分/会员入口，以及图片区和视频区的模型选择器。

本项目复刻这些**功能域与导航关系**，而非复制品牌文案、私有项目内容、会员价格、具体模型名称或社交数据。当前应用仍只使用本地 Dexie 存储和 `DemoGenerationAdapter`，因此不能把真实生成或帐号体系呈现为已完成能力。

## 3. 已有能力与保护边界

| 路由/能力 | 当前状态 | 本阶段处理 |
| --- | --- | --- |
| `/` 项目启动器 | 可创建配方项目、空白项目、示例与最近项目 | 保持所有创建与继续创作流程，置入平台壳 |
| `/project/:projectId` | React Flow 画布、节点、连线、生成队列、保存、键盘节点列表 | 原功能不变，进入工作区模式 |
| `/project/:projectId/preview` | 时间线、预览、排序、导出面板 | 原功能不变，进入工作区模式 |
| Dexie `ProjectRepository` | `load`、`save`、`listRecent` | 新页面只读取项目；不改变项目数据模型 |
| `DemoGenerationAdapter` | 以本地演示图片响应生成请求 | 在模型页明确为演示能力 |

`audit-2026-08-06/` 是用户受保护的未跟踪目录。本阶段不得读取、改动、删除、暂存或提交它。

## 4. 方案比较与选定方案

1. **独立占位页集合**：快速添加侧栏链接，但无法提供可验证任务，也会误导用户认为真实生成、账户或社区已接入。拒绝。
2. **全页固定仪表盘壳**：所有页面统一，但会压缩画布并违背 V1 的“画布是产品本体”。拒绝。
3. **自适应 PlatformShell（选定）**：普通页面使用完整侧栏、顶栏与内容容器；画布和预览使用同一导航语义，但以紧凑、可收起的侧栏维持工作区宽度。每个新增入口都有真实本地数据、可用导航或可验证过滤/选择交互。

## 5. 信息架构与路由

```text
无线画布 PlatformShell
├── 项目空间 `/`
│   ├── 创建项目（既有）
│   └── 最近项目（既有）
├── 创作画布 `/project/:projectId`
├── 素材与历史 `/assets`
│   ├── 活动项目素材
│   └── 节点版本与生成/导出记录
├── 工作流与模板 `/workflows`
│   └── 既有三种配方，可带入项目启动器
├── 发现与作品 `/discover`
│   └── 可打开的内置示例项目
├── 模型能力 `/models`
│   └── 当前演示适配器与后续真实接入边界
├── 本地工作区 `/account`
│   └── 本地持久化状态与后续账户能力边界
└── 成片预览 `/project/:projectId/preview`
```

旧路由不重定向、不改变参数，也不增加认证门槛。

## 6. 组件与数据边界

### 6.1 `PlatformShell`

`PlatformShell` 是路由布局，不拥有项目数据。它负责品牌入口、主导航、页面标题区域、键盘可访问的侧栏收起控制和普通内容容器。

- 普通模式：侧栏展开，内容宽度受容器限制。
- 工作区模式：侧栏改为紧凑图标轨，可由按钮收起；画布与预览保留全宽内容。
- 当前路由使用 `NavLink` 提供可见当前状态和 `aria-current`。
- 所有侧栏按钮与跳转保持可通过 Tab、Enter 与 Space 使用。

### 6.2 页面数据读取

新增页面共享只读 `ProjectRepository.listRecent()`：

- 素材与历史页以当前活动项目为优先项，并显示最近项目中的素材、版本数、任务状态和出口状态；缺少项目时给出到项目空间的明确行动入口。
- 工作流与模板页读取同一份配方目录；“使用此配方”会跳回 `/` 并写入 URL 查询参数，启动器据此选中配方，不自动创建项目。
- 发现与作品页展示内置示例的真实创作意图、节点数量和工作流标签；“打开示例”复用现有示例项目创建/持久化流程。
- 模型能力页展示由应用自有能力清单描述的“演示图像草稿”和“演示视频草稿”状态；筛选能切换图片/视频类别。此页不改变生成适配器，也不宣称远程模型可用。
- 本地工作区页展示持久化机制、最近项目数量和功能可用性矩阵；不模拟登录、积分、团队、权限或会员状态。

### 6.3 配方目录

既有三个项目启动配方移入独立目录模块，由启动器、工作流页和发现页共同消费。目录会导出 `RecipeDefinition`、稳定的 `RecipeId`、查找函数和 URL 查询参数名，避免三处内容漂移。

### 6.4 示例项目

既有示例项目构建函数移入专用模块。`ensureExampleProject` 先加载已有示例，缺失时写入，再激活并导航。这样发现页和启动器打开同一个真实项目，而不是各自生成视觉相同但 ID 不同的临时内容。

## 7. 页面行为与完成定义

| 页面 | 真实内容 | 可验证交互 | 明确不做 |
| --- | --- | --- | --- |
| 项目空间 | 既有创建、配方、最近项目 | URL 配方预选、创建和继续项目 | 云端团队项目 |
| 创作画布 | 原有节点、连线、生成、保存 | 原所有交互；侧栏收起 | 改造画布领域模型 |
| 素材与历史 | 项目资产、版本、生成/导出记录 | 项目筛选、打开来源画布 | 上传、删除、跨项目移动 |
| 工作流与模板 | 三个既有配方 | 选择后回到启动器并预选 | 任意新建/发布模板 |
| 发现与作品 | 内置示例项目 | 打开示例进入真实画布 | 公共社区、点赞、评论、发布 |
| 模型能力 | 演示适配器能力边界 | 图片/视频筛选 | 模型配置、付费、远程调用 |
| 本地工作区 | 存储、可用性与后续边界 | 返回项目空间 | 登录、会员、团队、协作 |
| 成片预览 | 原有播放器、时间线、导出 | 原所有交互；侧栏收起 | 专业多轨编辑 |

## 8. 视觉与响应式规则

- 延续现有深色、高对比、电影感 token；导航优先使用文字与图标并列，不只依赖图标。
- 宽视口的侧栏为 232px，工作区紧凑轨为 64px；收起后为 56px 图标轨，仍保留可访问名称与可见焦点。
- 低于 900px 时，普通侧栏以覆盖式导航显示；页面内容仍保留至少 16px 内边距。
- 不触碰画布内部节点的空间、缩放、工具栏、连线、键盘快捷键或节点列表替代视图。

## 9. 测试策略

测试遵循 TDD：每个生产行为先有失败的组件或路由测试，并确认它因缺少目标行为而失败。

1. `PlatformShell`：活动导航、工作区紧凑模式、收起状态与键盘可访问性。
2. 配方目录/项目启动：查询参数正确预选既有配方，不自动创建项目。
3. 新页面：空态、读取项目后的真实数据、过滤或打开动作。
4. 旧路由：`/`、画布、预览在壳内仍可渲染。
5. 浏览器：从项目空间进入工作流、预选配方、创建项目、进入画布、打开素材历史、回到预览；检查控制台无错误。
6. 门禁：focused Vitest、全量 Vitest、TypeScript typecheck、生产 build、Playwright 关键路径与 `git diff --check`。

## 10. 后续阶段清单

1. 真实生成：供应商适配器、模型参数、任务恢复、成本与错误处理。
2. 素材库：上传、标签、集合、跨项目引用、版本对比。
3. 剧本/角色/世界观：结构化创作实体及其到画布节点的双向映射。
4. 工作流：可编辑模板、节点化流程、导入导出、模板发布审核。
5. 专业剪辑：多轨、音频、转场、字幕、逐帧与渲染恢复。
6. 社区：作品发布、发现、创作过程、互动与审核。
7. 协作/会员：账户、组织、邀请、权限、计量、订阅与结算。
8. Agent/Skill/CLI：受控工具调用、可复现项目操作、审计记录与远程任务队列。

## 11. 非目标

本阶段不复制 LibTV 的私有数据、会员促销、积分、团队、收藏、社交关系或任何真实模型目录；也不迁移既有项目数据、重写生成队列、替换 Dexie、改造导出流程或增加服务器依赖。
