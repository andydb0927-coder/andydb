# 真实模型 API 对接清单

当前状态：**未对接。** 代码保留了图片、视频、文本和语音适配器，但公开构建强制 Mock，后端的 Key、模型 ID、语音资源 ID、邀请码和 CORS 白名单均默认为空。

这份清单由项目负责人在准备真实账号、资质和预算后执行；本次交付不代填、不验证、不保存任何密钥。

> 凭据卫生提醒：交付审计曾发现旧的本地 Mock 产物读取了 `.env.local` 中的 Kling 浏览器端 Key。该产物未推送、已被安全重建覆盖，当前产物独立复扫通过；但该 Key 仍应在供应商控制台立即轮换，后续不得复用。

## 1. 先决策部署路径

- [ ] 先轮换旧 Kling Key，确认旧值已失效，不将新值写入任何 `VITE_*` 公开构建变量。
- [ ] 公网或多人使用时只选“后端代理”；不把长期 API Key 写入 `VITE_*`、前端代码或静态托管环境。
- [ ] `seedream-direct-dev` 只用于个人本机短期调试，不得构建或上传该模式的 `dist`。
- [ ] 为真实调用设定独立测试账号、最低配额、单次成本上限和停机阈值。

## 2. 确认供应商资质

- [ ] 在供应商控制台确认当前账号确实可调用所需图片、视频、文本、TTS/音频能力。
- [ ] 记录账号可用的 Model ID 或 Endpoint ID；不从宣传页、截图或他人示例推断权限。
- [ ] 确认语音服务的专用 Key/资源 ID 和图片视频 Ark Key 的鉴权边界。
- [ ] 确认税费、限流、并发、内容审核、存储周期和地域网络约束。

## 3. 配置后端技术预览

在 `backend/` 中复制 `.dev.vars.example` 为本机 `.dev.vars`，然后仅在本机或部署平台 Secret 管理器填写：

- [ ] `DEVICE_TOKEN_SECRET`：独立、高强度、可轮换。
- [ ] `ADMIN_TOKEN`：与设备令牌密钥不同。
- [ ] `ARK_API_KEY`：只保存在后端 Secret。
- [ ] `OPENSPEECH_API_KEY`：如启用语音，只保存在后端 Secret。
- [ ] `INVITE_CODES`：保持为空；正式准入使用 D1 邀请码管理接口，不将长期邀请码编译进前端。

由项目负责人再填写 `backend/wrangler.toml` 或对应部署环境的非秘密变量：

- [ ] `SEEDREAM_MODEL_ID`
- [ ] `SEEDANCE_MODEL_ID`
- [ ] `ARK_TEXT_MODEL_ID`
- [ ] `OPENSPEECH_RESOURCE_ID`
- [ ] `CORS_ALLOWED_ORIGINS`：只列精确的 HTTPS 前端 origin，逗号分隔；不使用 `*`。

如使用 Cloudflare，Secrets 应通过平台的 Secret 命令/控制台录入，不提交 `.dev.vars`。

## 4. 连接前端

- [ ] 前端只配置 `VITE_BACKEND_URL=https://<your-api-origin>` 和 `VITE_GENERATION_MODE=cloud-proxy`。
- [ ] 不配置长期 `VITE_BACKEND_INVITE_CODE`；让用户在鉴权流程中提交邀请码。
- [ ] 公开环境不配置 `VITE_SEEDREAM_API_KEY` 或 `VITE_ARK_TTS_API_KEY`。
- [ ] 部署前检查 `dist` 中不包含 Key、邀请码、临时 Endpoint ID 或本机后端地址。

## 5. 低风险真实验证

- [ ] 每个供应商先做一次最小输入、最低成本的单次调用，记录 request ID、HTTP 状态、供应商任务 ID、费用和耗时。
- [ ] 分别验证 401/403、429、欠费、审核拒绝、超时、取消、重试和部分成功。
- [ ] 确认重试不会重复扣费，超时或前端取消不会被误报为“未计费”。
- [ ] 确认结果持久化、刷新恢复、版本还原、下载和导出都使用实际返回媒体。
- [ ] 把供应商实调证据与 fixture 自动化证据分开存放，报告中明确区分两者。

## 6. 生产前必须补齐

- [ ] 限流、滥用防护、成本上限和紧急断路。
- [ ] 令牌的安全存储、过期、轮换、注销和泄漏响应；不把 localStorage bearer 当作最终生产方案。
- [ ] 项目、任务、媒体和配额的服务端所有权校验。
- [ ] 云存储一致性、离线删除、冲突合并、备份恢复和审计日志。
- [ ] 应用、隐私、账号与内容安全评审，以及实际部署域名的 CORS 验证。
- [ ] 重跑前端四道门禁和后端类型/测试，再做独立人工验收。

在上述项目全部完成前，产品文案应保持“需配置”或“待接入”，对外只交付 `build:mock` 产物。
