## 二、架构搭建阶段（08-06 ～ 08-15）

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 前端框架 | Vite + React + TypeScript | 生态成熟、类型安全 |
| 画布引擎 | React Flow | 无限画布标准解 |
| 本地存储 | IndexedDB（版本化领域模型） | 纯前端零成本、刷新恢复 |
| 生成管线 | 任务状态机（TaskStatus 统一契约）+ Provider 注册表 | 多模型可插拔、状态可追溯 |
| 后端（后期） | Hono + Cloudflare Workers / D1 / KV → EdgeKV 适配层 | API Key 藏服务端、跨设备数据 |
| 部署 | GitHub Pages（SPA + 404 回退） | 零成本自动上线 |

**架构原则**（贯穿全程）：
- 生产/开发环境隔离：线上永远 mock，真实 Key 只在本机 `.env.local`
- 数据向后兼容：节点/连线/资产/历史多画布变更全部带版本迁移
- 诚实表达能力：REAL_LOCAL/LIVE_API/MOCK/STATIC/PARTIAL/PLACEHOLDER/BROKEN 每项有源码依据

## 六、真实验证阶段（本项目最值钱的一环）

预算 15 元，实际花费 ¥0.31 + 1 张 2K 图。发现并修复：

1. **Seedream 模型 ID 过期**（400）→ 改 `doubao-seedream-5-0-pro-260628` 真跑通过
2. **TTS 走错鉴权体系**（401）→ Ark Key 不能用于 OpenSpeech，诚实降级为"待专用资源授权"
3. **Seedance 404 根因**→ 视频高级权益是邀测企业用户专属，非代码问题
4. **账号欠费检测**→ 错误映射修复批（欠费给精确中文提示而非泛化错误）
5. **Cloudflare 边缘访问方舟北京不通**→ 促使 EdgeOne 迁移决策

**核心教训**：fixture 全绿 ≠ 真实供应商通过。花 0.31 元抓出了 5 个只在真实环境暴露的问题。

## 七、是否严格按 LibTV 教程开发？——诚实评估

### 结论：**功能覆盖面严格对标，开发方式是按"功能基准"产品化反推，不是照教程开发**

### 严格对标的部分 ✅
- 153 项功能逐项盘点，全部来自 LibTV 官方飞书指南反推
- 每个功能的状态（真实可用/占位/未实现）在 CSV 中有源码依据
- 画布交互（节点/连线/分组/资产/历史）、时间线、导演台、角色库等核心域全部覆盖
- 对照表在 `docs/superpowers/specs/2026-08-26-libtv-guide-gap-table.md`

### 与教程的差异（诚实列出）❌
1. **教程是"使用指南"不是"开发文档"**——它定义了"做什么"（功能清单）；"怎么做"（技术栈/架构/质量门禁）是我们自主选的。React Flow、IndexedDB、任务状态机这些教程里不存在。
2. **模型供应商不同**：教程是 liblib 平台能力（MJ/可灵/liblib 自研），我们走火山方舟（用户自有账号），价格/能力边界完全不同。
3. **官方不支持的能力没有硬凑**：音色克隆/人声分离/智能剪辑等 8 项，教程里有、火山方舟官方无端点——全部诚实占位+原因+参考价，而不是用假功能填充。
4. **大量功能超出教程范围**（自研扩展）：脚本 v2、风格系统、主体一致性、管线自动化、邀请码账号体系、配额计量——LibTV 指南里没有这些，是托管模式下追加的产品决策。
5. **工程标准高于教程要求**：四道门禁、273 布局审计、先红后绿、真实生成二次确认、诚实表达能力——这些是自设的质量门禁。

### 一句话总结
**LibTV 教程是我们的功能需求基准线（153 项全覆盖），不是施工图。** 产品长成了"功能对标 LibTV + 自研扩展 + 火山方舟真实 API + 自建后端账号体系"的形态——功能上不欠账，实现上完全自主。
