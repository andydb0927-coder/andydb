# 出海转绘批 3 · QA 自审与交付检查验收

## 本批范围

- 起点：`46d57e2`；分支：`codex/platform-shell-phase`。
- 纯前端检查器、九节清单、确认表快照、工作台审核门禁。
- 沿用独立 IndexedDB 工作台，不变画布与资产主结构，不接真实 API、不产生生成费用。
- [实现说明与规则边界](../superpowers/specs/2026-09-10-dubbing-qa-engine.md)。

## 功能核对

| 项目 | 实际结果 |
| --- | --- |
| 自动检查 | 集名/连续性、字幕区间与安全框、口型时间差、中文残留、语种数字、音量/声道、交付文件规格、返修次数均有纯函数检查。 |
| 判断诚实性 | 模板32条原始标准保持人工/AI待确认；11个自动子项独立出结果，不以子项PASS冒充整个标准通过。未知或缺失数据WARN。 |
| 自审门禁 | 全32子项+九节逐集排查+无自动FAIL+当前确认表；UI与仓储共同校验，不能靠只勾P0通过。 |
| 快照 | 含版本、项目/集/镜号、语种、确认人、时间、规则及原始依据，可查看/复制，刷新仍在。 |
| 失效处理 | 返修新版本清空当前QA；数据/方案变更重新确认；旧自审快照保留。 |
| 兼容 | 仅独立qa对象新增可选字段，无数据库清除或画布迁移；批2三个返修轮次和跨项目隔离保留。 |
| 键盘/错误 | Esc关闭检测数据弹窗并归还焦点；非法JSON和非法结构中文提示；剪贴板失败提供手动复制。 |
| 视口 | 1440/1280/1024 浏览器验收，页面无横向溢出，三栏内滚动；截图已人工审阅。 |

## TDD 与问题记录

1. 自动检查器测试先因模块不存在失败，随后实现规则。
2. 清单仓储先因原有仅P0门禁及新方法缺失失败，随后加入完整清单和快照校验。
3. 数据保存必须使勾选失效；对应FAIL阻断测试补齐保存后的重新勾选步骤，不改变该产品规则。
4. 新UI测试发现原生details也具有group语义，改为逐节按名称断言，仍要求九节完整。类型检查随后发现误用Playwright的exact选项，删除Testing Library不支持的参数，从第一门禁重跑。
5. 浏览器定向3/3通过：原返修与交付、新增自审流程、原三视口与方案保存。全过程fixture，未调用真实供应商。
6. 首轮完整单测1723通过/1失败：旧测试把返修弹窗内已输入的意见当作保存完成，数据库提交而React尚未更新时读取下一步按钮。依据失败DOM改为等待弹窗消失、详情中意见出现和下一状态按钮，再做原断言；未改产品保存逻辑，未延长全局超时或删测试。失败日志归档，修正后从第一门禁重跑。

## 明确边界

- 元数据来自人工登记，不是媒体探测报告；未知数据不会被伪造为符合。
- 客户PDF没有在本批重新解析；沿用批1模板。安全框5%–95%为项目默认常量，需按客户最终标准确认。
- 机器WARN保持原状；用户勾选是“已核对符合或确认不适用”的人工声明，不是AI已经检测通过。
- “提交生成”仍是将已有结果纳入待自审；审核门禁位于“标记自审通过”。本批不启动生成、不代替客户验收或实际文件交付。
- 原有三张未提交截图保持原样，自动测试覆盖的既有证据从开工备份恢复；只提交本批证据。
