# 新功能批次8：工作流自动化验收

## 范围与边界

- 基于 `codex/platform-shell-phase` / `458f7ced18f993ad6f0f288501d5514e21cb1f05`，原基线 189 文件 / 1556 单测 / 121 E2E。
- 本批只增加前端管线调度、模板与本地执行记录；复用模型注册表、`GenerationQueue`、`TaskStatus`、版本/资产/历史保存路径。没有改供应商传输协议，没有新后端或定时服务。
- 所有自动化使用隔离浏览器、独立端口和 fixture 拦截。未读写 `.env.local`，未执行真实付费生成。fixture 通过不等于真实供应商端到端验收。

## 操作卡

1. 选中脚本、文本或图片起点，右键「执行下游管线」；也可点击顶栏「管线自动化」图标选择起点。
2. 检查按连线拓扑列出的节点，逐步选择「按节点模型生成」「使用现有结果」；图片还可选「本地图片后处理」，配置水平/垂直镜像与旋转。
3. 选择失败策略：失败即暂停、继续独立分支、自动重试 1–3 次。点击「执行整条管线」，查看预计成本/重试预算并确认。
4. 执行面板显示每步状态、进度、次数与中文错误，画布节点同步徽标。可跳过未执行/失败步骤、重试失败步骤、暂停或取消。
5. 「管线模板」可保存、重命名、删除或创建管线；「执行历史」可查看本画布每次运行的耗时、节点数、成功/失败/跳过数与步骤详情。

## 数据与安全决策

| 边界 | 行为 |
| --- | --- |
| 执行范围 | 起点与其可达下游；复用拓扑校验拒绝循环、悬空边；每步使用上游新结果 |
| 生成路径 | 注册表分发，不偷偷回退演示模型；未配置/不支持的模型或工具明确说明 |
| 本地后处理 | Canvas 读取真实上游图片，镜像/旋转后写入新资产与版本，成本为 0 |
| 暂停/取消 | 暂停等待当前步骤完成；取消 Abort 当前步骤并保留已完成。供应商已接单不保证免单 |
| 失败继续 | 仅继续独立分支；依赖失败分支标记跳过，不拿旧图冒充本次新结果 |
| 本地保存失败 | 暂停且不自动再次生成；成功任务的重试只补保存 |
| 刷新/切项目/切画布 | 不自动发请求；关联已保存 Job 恢复已完成步骤，其余等待手动继续 |
| 运行存储 | IndexedDB v12 追加 `pipelineRuns`、`pipelineTemplates`；旧表/旧节点兼容保留 |
| 模板 | 保留类型、输入、模型参数、风格与拓扑；移除结果、媒体 URL、外部素材/主体引用；创建时重新分配 ID |
| 隔离 | 历史按项目+画布过滤；旧项目的迟到结果不能写入新项目 |

## 已知限制与回滚

- 这是当前浏览器内的串行调度，不是后台无人值守任务；关闭页面不会继续调度后续节点。刷新后需要手动继续，已发出的第三方任务可能仍计费。
- 模板不带媒体结果与外部引用，使用已有结果的步骤需要补充素材。未接入工具不会被伪装成成功。
- 原始 Vitest 日志包含基线已有的 `localhost:3000` 连接异常 stderr；构建仍有 CanvasPage chunk 大于 500kB 的提示，保留原始日志，不作为新功能成功证明。
- 回滚界面/调度时必须保留 IndexedDB v12 的两张新增表声明，避免已有 v12 数据库被较低版本号代码打开而报版本错误；不通过删库回滚。已生成资产、原项目与旧历史均不删除。
