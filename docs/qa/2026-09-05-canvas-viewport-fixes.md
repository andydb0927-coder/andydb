# 画布编辑区与视口恢复修复

日期：2026-09-05。工作树：`codex/platform-shell-phase`，起始提交 `af3e828`。

## 本批范围

延续 LibTV 式「上浮标题 + 媒体卡 + 下方独立 composer」构图，修复本次审计确认的两处操作问题，以及回归中发现的评论栏/缩放控件冲突。不新增模型，不改生成 API、项目数据结构或供应商配置，不调用付费生成，不部署线上。

| 编号 | 问题与根因 | 修复 |
| --- | --- | --- |
| BUG-018 | 空画布创建第一个图片/视频/文本节点时只按节点本体处理可视范围，屏幕尺寸固定的 composer 可能落在底边之外；普通 DOM 滚动不能替代画布平移。 | 仅对单节点画布启用编辑区可达性逻辑，等待测量稳定后按媒体、标题、composer 与结果操作的屏幕边界作必要缩小和平移；避让工具坞和结果工具条，在空间允许时避让评论栏。 |
| BUG-019 | 加载已保存视口后，React Flow 的初始 `fitView` 又按节点范围适配，覆盖已保存的平移/缩放。 | 仅创建后从未编辑且视口为初始值的画布保留首次适配；其他画布恢复其保存视口。用户显式点「适配画布」及定位节点的行为保留。 |
| BUG-020 | 评论栏与缩放控件都占用右上角，折叠按钮拦截 Zoom In 点击。 | 评论栏预留独立的缩放控件通道；同时按剩余视口宽度约束评论栏，避免把遮挡转移到窄屏左边。 |

## 边界与决策

- 自动调整限单节点画布、单选且不在连线/参考选择模式时生效，不由提示词更新或用户手动平移缩放触发。缩放与平移同时更新，用户开始拖动、缩放、输入即中止待执行的后续调整，不留下半完成的视角。
- 多节点画布保留原视角和布局，不在选中节点后移动其他连接目标；多节点场景的编辑浮层独立避让留待下一轮，不将本批描述成全场景自动定位或 LibTV 完整 1:1 验收。
- 单节点窄布局使用画布可用宽度；600–800px 宽度采用紧凑参数网格，不缩小提示词字体、不隐藏生成按钮。721×720 空图片节点实测媒体卡、提示词和生成参数可完整同屏。极小高度、超长编辑器或竖图超出最小缩放可容纳范围时，保留媒体与右键入口，仍可手动导航；不声称任意内容在任意视口均完整同屏。
- 保留最小缩放限制与原节点布局；处理变换坐标的亚像素舍入，避免几乎刚好适配时错误舍弃媒体及「加入时间线」操作。
- 未读取 `.env.local`，全量构建显式用 `build:mock`；浏览器使用新上下文、独立端口与 fixture，未清理用户数据。
- 测试前备份既有证据文件，测试后恢复与本批无关的历史截图；不回退用户原有改动。

## 回归证据

新增 `e2e/canvas-viewport-regression.spec.ts` 共 7 项：图片 1280/1024/721 三种宽度首次展开时媒体卡与编辑区同屏、可输入、可选参数与命中生成按钮，缩放按钮可真实 hover；视频/文本首次展开可输入；刷新、切画布、离开并重进项目恢复保存视口；已有多节点图切换选中节点不改变视口。图片输入前后视口一致。

新增纯函数单测 11 项：5 项几何计算（缩放计算、已适配不扰动、最小缩放、最小平移、空间不足时保留内容起始位置），4 项首次适配判定（新画布、已编辑后保存初始视角、保存非初始视角、未加载），2 项缩放锚点不漂移。

先红：新增 6 项 E2E 均复现失败；视频/文本 composer 可视比例约 0.057/0.086，保存视口重开 x 偏移约 459px。修复期间原「短片创作闭环」也检出结果操作出界，现已一并修复，原断言未删减。

回归过程中拒绝了「对全部选中节点自动平移」的实现：它会移动其他连接目标并干扰既有操作。中间全量检查为 129 通过、16 失败，日志保留在 `playwright-rejected-broad-autofocus.log`，不是交付结果。收紧到单节点场景并恢复新画布首次适配后，14 项定向检查全部通过（含连续引用拉线、原生连线、Option 拖拽复制、图片参数与参考选择）。更早中止的一轮日志为 `playwright-first-pass-interrupted.log`。最终门禁如下。

上述 16 项失败中，最后一项离线多视口检查遇到 `dist/index.html` ENOENT，是中间重建 dist 与尚未结束的离线检查重叠所致，不归类为产品缺陷。最终轮严格按类型检查→单测→构建→浏览器顺序，浏览器执行期间不重建或修改源码。

随后全量复验检出竖图上传后的右键入口被顶栏遮挡，主动中止（110 通过、1 失败、2 中止、33 未跑），保留 `playwright-portrait-regression-interrupted.log`。原因是空间不足时只优先露出 composer，反而把图片本体推到画布外；改为保留媒体与右键入口后，上传建主体和本批 7 项回归等 10 项定向检查全部通过。失败断言未删改，最终四道门禁重新完整执行。

快速打开角色库的回归又发现缩放先应用、平移下一帧才执行的中间态；用户操作取消后续调整会留下偏移（[中间态截图](evidence/2026-09-05-canvas-viewport/before/zoom-interrupted.jpeg)）。该轮 142 通过、2 失败、1 中止、1 未跑，保留 `playwright-interrupted-zoom-regression.log`。最终实现先按 CSS 实际变换原点预测缩放后的媒体与 composer 边界，再一次性应用缩放和平移；不会只完成缩放就被打断。
